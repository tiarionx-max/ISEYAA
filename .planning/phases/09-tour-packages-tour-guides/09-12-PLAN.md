TOUR-10: "All existing 282+ tests still pass; wallet ledger invariant test extended to verify multi-vendor split sums match buyer payment exactly (no drift); new TourGuide KYC encryption test verifies NIN never persisted plaintext."

This plan adds 3 dedicated specs and a small E2E test harness. The unit-level versions are covered by 09-03 (KYC spec) and 09-06 (settlement spec). Those specs are NECESSARY but not SUFFICIENT for TOUR-10 — they mock Prisma. TOUR-10 wants regression-grade tests that exercise the **real Prisma client** against a real PostgreSQL database (or an in-memory equivalent), to catch issues that mocks miss (transactional semantics, FK violations, ENUM mismatches, JSONB serialization edge cases, CHECK constraint enforcement, decimal precision).

**E2E harness strategy:** Use the existing E2E Jest config (`backend/test/jest-e2e.json` if present; if not, create it modeled on a standard NestJS e2e config). Bootstrap a fresh NestApplication via `Test.createTestingModule({ imports: [AppModule] })`. Connect to a dedicated test database (set DATABASE_URL_TEST in env; or reuse the dev DB with a transactional rollback wrapper). For schema state: rely on `prisma migrate deploy` running against the test DB before specs.

If the project does NOT have a Postgres-backed E2E test harness yet, this plan creates a minimal one in `backend/test/setup-e2e-tours.ts` (one-time DB reset + seed helpers) and the 3 specs use it. The harness MUST clean its own state between tests (truncate tour_bookings, transactions for tour module references, tour_packages, tour_guides between tests — preserve users + lgas seeded once at the top).

**TOUR-10 success criteria for each spec:**

1. **wallet-invariant.e2e-spec.ts** — at minimum 6 assertions:
   a. Total CREDIT sum across all vendor wallets + platform wallet == buyer chargeAmountNgn (3 distinct chargeAmounts: 1000 NGN, 50000 NGN, 1000000 NGN).
   b. Each vendor wallet's balance increased by exactly its `percentage * chargeAmount / 100` (rounded 2dp).
   c. Platform wallet balance increased by the complement (chargeAmount - sum(vendor credits)).
   d. Replay the same webhook -> NO additional Transaction rows written; balances unchanged.
   e. ATTRACTION-fallback: with government wallet PlatformConfig.value=null, attraction share rolls into platform; total still equals chargeAmount.
   f. Failed settlement path: stub `tx.wallet.update` for a vendor wallet to throw — assert NO Transaction rows persisted (rollback) AND RefundService.refund called once.

2. **kyc-encryption.spec.ts** — at minimum 4 assertions:
   a. After submitKyc, `prisma.tourGuide.findUnique` returns a row with non-null `ninCiphertext` that does NOT equal the plaintext NIN.
   b. The ciphertext is decryptable via `EncryptionService.decrypt` to the original NIN.
   c. `ninHash` is present, length consistent with bcrypt (60 chars), starts with `$2`.
   d. No log line emitted during submitKyc contains the plaintext NIN — capture via `jest.spyOn(Logger.prototype, 'log' | 'warn' | 'error' | 'debug')` and assert no captured argument string contains the NIN substring.
   e. (bonus) submitting the same NIN from a different guide hits the duplicate-hash ConflictException.

3. **e2e-tour-booking.e2e-spec.ts** — full happy-path walkthrough:
   1. Create 3 users via direct prisma.user.create (or via the auth endpoint): tourist, guide, host. Create a wallet for each.
   2. Promote guide via `POST /users/me/become-guide` with guide's JWT.
   3. Submit KYC for guide.
   4. LGA_ADMIN approves the guide via `POST /admin/tour-guides/:id/approve`.
   5. Create a TourPackage via `POST /tour-packages` with valid splits (GUIDE 60% / HOST 40%); submit for review.
   6. Admin approves package via `POST /admin/tour-packages/:id/decide`.
   7. Tourist creates booking via `POST /tour-bookings` with a future tour date.
   8. Assert response.payment.authorizationUrl present (Paystack mock returns stub URL).
   9. Synthesize a charge.success webhook payload, sign it via the Paystack secret, POST to /webhooks/paystack.
  10. Assert: booking.status === 'CONFIRMED', itinerary materialized, vendor wallets credited, platform commission row exists.
  11. POST a review via /reviews with rating=5 — assert it persists, no auto-flag.

Output: 3 specs + 1 E2E setup helper. May add a Jest e2e config if one doesn't exist.
