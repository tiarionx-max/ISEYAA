<objective>
**Highest-risk plan in Phase 9.** Multi-vendor settlement runs inside ONE Prisma `$transaction` per Paystack `charge.success` event with `metadata.type='tour_booking'`. Any deviation from the locked pattern risks double-credit, lost commission, or money silently disappearing.

**Architectural commitments (LOCKED in CONTEXT §Multi-vendor commission split):**
1. Use existing wallet ledger primitive `SELECT FOR UPDATE` proven in `wallet.service.ts:272`.
2. ONE Prisma `$transaction` per buyer payment success. Inside:
   - Lock buyer's wallet row (read-only — buyer wallet is NOT debited; Paystack already took the money from card).
   - For each vendor in `settlementSplit[]`: lock vendor wallet, write CREDIT Transaction, increment balance.
   - Write platform commission Transaction for the remainder.
   - Update TourBooking status to CONFIRMED (for solo; deferred for split-bill children).
3. ANY failure inside the transaction -> entire rollback -> `RefundService.refund` Paystack chargeback (09-02).
4. Idempotency keyed on Paystack reference: replay = no-op. Implementation: precheck for a Transaction row with `reference startsWith <paystackReference>-V-`. If any row exists -> return.
5. NO Kafka inside the settlement itself — runs inline in the handler. Kafka emit in WebhooksService is preserved.

**Wallet resolution per vendorType** (mirrors 09-04 validation):
- GUIDE -> `tourGuide.findUnique({ id: vendorId, select: { userId } })` -> wallet via `userId`.
- HOST -> `property.findUnique({ id: vendorId, select: { hostId } })` -> wallet via `hostId`.
- ORGANISER -> `event.findUnique({ id: vendorId, select: { organizerId } })` -> wallet via `organizerId`.
- ATTRACTION -> read `tour.government_wallet_user_id` from PlatformConfig. If set, wallet via that userId. If NULL, `logger.warn` and roll this share into platform commission. NEVER fail the settlement on unconfigured government wallet (would block all tour bookings).

**Reference scheme for ledger rows** (idempotency-friendly):
- Each vendor CREDIT: `reference = <paystackReference>-V-<idx>` where idx is index in settlementSplit[].
- Platform commission: `reference = <paystackReference>-PLAT`.
- For split-bill children, `paystackReference` is the CHILD reference (each child settles independently against the same percentages).

**Wallet invariant (TOUR-10):**
- `sum(vendor credits) + platform commission == buyer payment amount` to-the-kobo.
- Spec proves this for: 100% split, 80% split (platform takes 20%+), ATTRACTION-fallback (government wallet null).

**Platform commission formula:**
- `claimedAmountNgn = sum(round((entry.percentage / 100) * chargeAmountNgn, 2))` for entries with resolved wallets
- `platformAmountNgn = chargeAmountNgn - claimedAmountNgn` (absorbs all rounding drift)
- `abs(rounding drift) <= 0.02` enforced via assert; if violated, throw to trigger refund (defensive)

**Split-bill handling** (per 09-05 flow):
- Settlement runs identically for the share amount (`unitPrice`) — the same percentages apply per share.
- After the wallet transaction commits, append `metadata.shareKey` to `splitBillPaidUserIds` via a SEPARATE update (array mutation is independent of wallet locks).
- Then check `splitBillPaidUserIds.length >= passengerCount` -> transition to CONFIRMED.

**Platform/system wallet (Discretion call):**
- A dedicated SYSTEM user + wallet receives the platform commission row. On `onModuleInit`, the service upserts a single well-known SYSTEM user (id `00000000-0000-0000-0000-000000000001`, firstName `Platform`, lastName `System`, role `SUPER_ADMIN`, ndpaConsent: true) and its wallet. This is the v1 ops audit anchor; a proper SystemWallet model is a future refactor.

Output: A new `TourSettlementService` (added to the existing tour-bookings module) + the `tour_booking` case added to `WebhooksService.handlePaystack` + 2 specs (settlement service unit tests + webhook dispatch test).
</objective>

  **Algorithm — `handleTourBookingPayment(payload)`:**

  Step 1 — Resolve booking
    - if (!payload.metadata?.bookingId) { logger.warn; return }
    - const booking = await prisma.tourBooking.findUnique({ where: { id: payload.metadata.bookingId } })

  Step 2 — Idempotency precheck
    - const existing = await prisma.transaction.findFirst({ where: { reference: { startsWith: payload.reference + '-V-' } } })
    - if (existing) { logger.log('Settlement already applied for ' + payload.reference); return }

  Step 3 — chargeAmountNgn = payload.amount / 100

  Step 4 — Resolve settlement entries from the SNAPSHOT
    - const split = (booking.snapshot as any)?.settlementSplit ?? []
    - const govWalletConfig = await prisma.platformConfig.findUnique({ where: { key: 'tour.government_wallet_user_id' } })
    - const govWalletUserId = (govWalletConfig?.value as string | null) ?? null
    - const resolved: { idx: number, entry: SplitEntry, walletId: string | null, amountNgn: number }[] = []
    - for (let idx = 0; idx < split.length; idx++) {
        const entry = split[idx]
        let walletUserId: string | null = null
        switch (entry.vendorType) {
          case 'GUIDE':
            const g = await prisma.tourGuide.findUnique({ where: { id: entry.vendorId }, select: { userId: true } })
            walletUserId = g?.userId ?? null; break
          case 'HOST':
            const p = await prisma.property.findUnique({ where: { id: entry.vendorId }, select: { hostId: true } })
            walletUserId = p?.hostId ?? null; break
          case 'ORGANISER':
            const ev = await prisma.event.findUnique({ where: { id: entry.vendorId }, select: { organizerId: true } })
            walletUserId = ev?.organizerId ?? null; break
          case 'ATTRACTION':
            walletUserId = govWalletUserId
            if (!walletUserId) { logger.warn('Attraction ' + entry.vendorId + ' rolled into platform — tour.government_wallet_user_id is unset'); }
            break
        }
        const wallet = walletUserId ? await prisma.wallet.findUnique({ where: { userId: walletUserId } }) : null
        const amountNgn = Math.round((entry.percentage / 100) * chargeAmountNgn * 100) / 100
        resolved.push({ idx, entry, walletId: wallet?.id ?? null, amountNgn })
      }

  Step 5 — Compute platform commission
    - const claimedAmountNgn = resolved.filter(r => r.walletId).reduce((s, r) => s + r.amountNgn, 0)
    - const platformAmountNgn = Math.round((chargeAmountNgn - claimedAmountNgn) * 100) / 100
    - const drift = chargeAmountNgn - claimedAmountNgn - platformAmountNgn
    - if (Math.abs(drift) > 0.02) throw new Error('Settlement drift exceeded 0.02 NGN — possible programming error') // defensive

  Step 6 — Atomic $transaction

        for (const r of resolved.filter(x => x.walletId)) {

          const w = await tx.wallet.findUnique({ where: { id: r.walletId! } })
          if (!w) throw new Error('Vendor wallet vanished mid-transaction ' + r.walletId)
          const before = Number(w.balance)
          const after = before + r.amountNgn
          await tx.wallet.update({ where: { id: r.walletId! }, data: { balance: after } })
          await tx.transaction.create({
            data: {
              walletId: r.walletId!,
              type: 'CREDIT',
              status: 'SUCCESS',
              amount: r.amountNgn,
              currency: 'NGN',
              reference: payload.reference + '-V-' + r.idx,
              gateway: 'PAYSTACK',
              gatewayRef: payload.reference,
              description: 'Tour booking commission (' + r.entry.vendorType + ')',
              balanceBefore: before,
              balanceAfter: after,
              metadata: {
                module: 'tour',
                bookingId: booking.id,
                vendorType: r.entry.vendorType,
                vendorId: r.entry.vendorId,
                packageName: (booking.snapshot as any)?.name ?? null,
                percentage: r.entry.percentage,
              },
            },
          })
        }
        // Platform commission row
        await tx.$executeRaw`SELECT id FROM wallets WHERE id = ${this.systemWalletId} FOR UPDATE`
        const sysW = await tx.wallet.findUnique({ where: { id: this.systemWalletId } })
        if (!sysW) throw new Error('System wallet missing')
        const sysBefore = Number(sysW.balance)
        const sysAfter = sysBefore + platformAmountNgn
        await tx.wallet.update({ where: { id: this.systemWalletId }, data: { balance: sysAfter } })
        await tx.transaction.create({
          data: {
            walletId: this.systemWalletId,
            type: 'CREDIT',
            status: 'SUCCESS',
            amount: platformAmountNgn,
            currency: 'NGN',
            reference: payload.reference + '-PLAT',
            gateway: 'PAYSTACK',
            gatewayRef: payload.reference,
            description: 'Tour platform commission',
            balanceBefore: sysBefore,
            balanceAfter: sysAfter,
            metadata: {
              module: 'tour',
              bookingId: booking.id,
              chargeAmountNgn,
              claimedAmountNgn,
              attractionsRolledIn: resolved.filter(r => r.entry.vendorType === 'ATTRACTION' && !r.walletId).map(r => r.entry.vendorId),
            },
          },
        })
        // Solo: confirm immediately
        if (!payload.metadata?.shareKey) {
          await tx.tourBooking.update({
            where: { id: booking.id },
            data: { status: 'CONFIRMED', paymentReference: payload.reference },
          })
        }
      })
    } catch (err) {
      await this.handleSettlementFailure(payload, booking, err as Error)
      throw err
    }

  Step 7 — Outside the transaction: split-bill bookkeeping
    if (payload.metadata?.shareKey) {
      const updated = await prisma.tourBooking.update({
        where: { id: booking.id },
        data: {
          splitBillPaidUserIds: { push: payload.metadata.shareKey },
          metadata: { /* merge in shares[shareKey] = { status: 'PAID', paidAt } */ },
        },
        select: { splitBillPaidUserIds: true, passengerCount: true },

          where: { id: booking.id },
          data: { status: 'CONFIRMED', paymentReference: payload.metadata.parentReference ?? payload.reference },
        })
        this.eventEmitter.emit('tour_booking.confirmed', { bookingId: booking.id, reference: payload.metadata.parentReference ?? payload.reference })
      }
    } else {
      this.eventEmitter.emit('tour_booking.confirmed', { bookingId: booking.id, reference: payload.reference })
    }
