**SC1 — TOUR_GUIDE role + onboarding + KYC + availability**
- Log in as a citizen user on mobile.
- Navigate to You tab → "Become a guide" (or hit `/become-a-guide` on web).
- Complete the flow: bio, languages, certifications, KYC NIN.
- Verify in DB: `SELECT id, status, ninCiphertext, ninHash, kycTier FROM tour_guides WHERE userId='<userId>'` — `ninCiphertext` is NOT plaintext NIN; `ninHash` starts with `$2`; status='PENDING'.
- Log in as LGA_ADMIN on web → `/admin/guides/queue` → click Approve.
- Refresh: status='APPROVED'.

**SC2 — TourPackage CRUD with structured itinerary + settlement split**
- Logged in as the now-APPROVED guide on web, navigate to `/host/tours/new`.
- Walk all 5 steps: basics, components (pick attractions/property/events), itinerary builder, settlement split (verify sum guard refuses > 100%), review + submit.
- Verify in DB: row in tour_packages with status='PENDING', itineraryTemplate JSON populated, settlementSplit JSON populated.
- Log in as LGA_ADMIN → `/admin/tours/queue` → Approve.
- Refresh: status='APPROVED'.

**SC3 — Tourist search + date constraint**
- Log in as tourist on mobile → Book hub → Tours sub-section.
- Toggle category tabs; verify packages filter.
- Tap a package; on tours/[id], select a tourDate that falls within an existing blockedDate; tap Reserve → backend returns 400 "Guide unavailable" — assert.
- Pick an unblocked date with passengerCount=3; tap Reserve → Paystack URL opens.

**SC4 — Atomic multi-vendor split on payment success**
- Use Paystack test card to complete the payment.
- After webhook arrives, query: `SELECT reference, type, amount, walletId, metadata FROM transactions WHERE reference LIKE '<ISY-TOUR-...>%' ORDER BY createdAt`.
- Verify: 1 CREDIT row per resolved vendor + 1 -PLAT row for platform commission.
- Verify: `sum(amount) == bookingTotalAmount` (NGN, to-the-kobo).
- Verify: tourBooking.status moved to CONFIRMED.

**SC5 — Itinerary 3-channel delivery**
- After CONFIRMED, check the buyer's email inbox: email arrived with subject containing package name + PDF link OR PDF attachment.
- On mobile: navigate to You tab → My Trips → tap the booking — itinerary timeline rendered with per-item datetimes.
- 24h before tourDate (or simulate by adjusting `tour.notify_t_minus_24h_hours` to 0 temporarily): the cron job sends a push. Verify on mobile device the push notification arrives within 1 hour.

**SC6 — Group + bulk discount + split-bill**
- Create a new booking with passengerCount=15: verify unit price shows tier-1 discount (e.g. 10% off pkg.price).
- Create a booking with passengerCount=30: verify tier-2 (20%).
- Create a booking with passengerCount=10 + splitBillEnabled=true: receive splitBillJoinLink. Share to a second test device → second user opens the deep link → join endpoint init Paystack for unitPrice → after payment, splitBillPaidUserIds updates. Repeat until all 10 shares paid → booking transitions to CONFIRMED.
- Test closeSplitBill: with 7 of 10 paid, group leader hits Close → backend initiates Paystack for remaining 3 shares.

**SC7 — Post-tour rating + auto-flag**
- Wait for (or simulate) a CHECKED_OUT booking. On mobile, tap "Rate your tour" notification or open /tours/rate/:bookingId.
- Submit 3 ratings: guide=5 / package=4 / venue=2.
- Verify in DB: 3 reviews persisted. The venue review has flagged=true AND a row in admin_review_flags with status='OPEN'.
- On web /admin/reviews/queue: the flag appears. Click Resolve → status='RESOLVED'.
