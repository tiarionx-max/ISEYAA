<objective>
Implement the booking-side of TOUR-03/TOUR-05/TOUR-06. **This plan deliberately does NOT touch wallet ledgers** — all multi-vendor settlement is plan 09-06's atomic webhook handler. Splitting this way limits blast radius: this plan can break in 1 transaction (the booking insert) and still leave the wallet ledger clean.

**Date constraint check** (TOUR-03 SC #3):
1. `tourDate` must be a future date.
2. ISO `YYYY-MM-DD` must NOT appear in `tourGuide.availability.blockedDates`.
3. `new Date(tourDate).getUTCDay()` must NOT appear in `tourGuide.availability.weeklyOffDays`.
4. For each `eventId` in package: Event must exist with status in {APPROVED, PUBLISHED}, and `startDate <= tourDate <= endDate`. If any event conflicts, refuse with the event title.
5. Attraction opening hours NOT enforced in v1 (Attraction schema has no opening-hours fields; flagged for follow-up).

**Bulk discount** (TOUR-06):
- passengerCount 1-9: unitPrice = package.price
- passengerCount 10-24: unitPrice = round2(package.price * (1 - tour.bulk_discount_t1))
- passengerCount 25-50: unitPrice = round2(package.price * (1 - tour.bulk_discount_t2))
- passengerCount > 50: 400 BadRequest "Contact corporate sales for groups over 50"
- totalAmount = unitPrice * passengerCount (for split-bill, parent totalAmount accrues as shares are paid via the webhook).

**Split-bill flow** (Discretion pick #6 — N separate Paystack init calls, NOT Paystack split feature):
1. Group leader creates TourBooking with `splitBillEnabled: true`. Parent reference = `ISY-TOUR-<12char>`. Status starts PENDING. Parent is NOT immediately Paystack-initiated; instead the response carries a deep link `iseyaa://tour-booking/{id}/join`.
2. Each passenger calls `POST /tour-bookings/:id/join` with their email. Endpoint mints a NEW child reference `ISY-TOUR-<12char>` and initiates a separate Paystack payment for `unitPrice` (one share). Child ref is recorded in `metadata.shares` on the parent booking.
3. Plan 09-06's webhook handler treats EACH successful payment as a share: appends payer userId to `splitBillPaidUserIds`. When `splitBillPaidUserIds.length >= passengerCount`, parent transitions to CONFIRMED.
4. Group leader can call `POST /tour-bookings/:id/close` to absorb the remaining shares (single Paystack init for `remaining * unitPrice`).

**Itinerary materialization** at booking time:
- Read `package.itineraryTemplate` array of `{ hour, title, description, location? }`.
- Compute `datetime = tourDateStart (08:00 UTC) + (hour * 3_600_000) ms` for each item.
- Write to Itinerary.items as `[{ hour, title, description, location?, datetime: ISO }]`.
- Link via TourBooking.itineraryId.
- PDF generation is plan 09-07.

**Snapshot capture**: at booking time, copy the TourPackage lean projection onto `TourBooking.snapshot` so subsequent package edits don't mutate historical bookings (CONTEXT §deferred §versioning).

Output: A new `tour-bookings` NestJS module + 2 DTOs + 5 endpoints + a spec exercising all the date-constraint + bulk discount + split-bill cases.
</objective>

  function isBlockedDate(availability: any, tourDateIso: string): boolean {
    const blocked = (availability?.blockedDates as string[]) ?? [];
    if (blocked.includes(tourDateIso)) return true;
    const weeklyOff = (availability?.weeklyOffDays as number[]) ?? [];
    const dow = new Date(tourDateIso + 'T00:00:00Z').getUTCDay();
    return weeklyOff.includes(dow);
  }

  function applyBulkDiscount(price: number, passengerCount: number, t1: number, t2: number): number {
    if (passengerCount <= 9) return price;
    if (passengerCount <= 24) return Math.round(price * (1 - t1) * 100) / 100;
    return Math.round(price * (1 - t2) * 100) / 100;
  }

  function materializeItinerary(template: any[], tourDateIso: string) {
    const base = new Date(tourDateIso + 'T08:00:00Z');
    return template.map(item => ({
      hour: item.hour,
      title: item.title,
      description: item.description,
      location: item.location,
      datetime: new Date(base.getTime() + item.hour * 3_600_000).toISOString(),
    }));
  }
