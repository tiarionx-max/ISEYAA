Endpoints consumed:
  GET  /api/v1/tour-packages?category=&lgaId=&page=&limit=    (public, status=APPROVED enforced server-side)
  GET  /api/v1/tour-packages/:slug                            (public, hydrated detail)
  POST /api/v1/users/me/become-guide                          (auth, returns updated user)
  POST /api/v1/tour-packages                                  (auth TOUR_GUIDE, returns DRAFT package)
  POST /api/v1/tour-packages/:id/submit                       (auth, DRAFT -> PENDING)
  POST /api/v1/tour-bookings                                  (auth, returns { booking, payment? OR splitBillJoinLink? })

TourBookingForm submit branching (mirrors 09-05 service response):
  - response.payment?.authorizationUrl -> window.location.href = url (Paystack handoff)
  - response.splitBillJoinLink         -> show share modal with copy button + WhatsApp share intent

Multi-step form steps (/host/tours/new):
  Step 1: Basics — name, description, category, lgaId, price, durationHours, maxGroupSize, coverImageUrl
  Step 2: Components — pick 1+ attractions (multi-select), optional property, optional events, optional transportNote
  Step 3: Itinerary — list builder with row { hour, title, description, location? } — add/remove rows, sort by hour ascending
  Step 4: Settlement split — list builder with row { vendorType, vendorId, percentage } — show running sum + visual gauge; refuse continue if > 100
  Step 5: Review + Submit — preview the package; on Submit, POST /api/v1/tour-packages then POST /:id/submit. Redirect to /host/dashboard (or stub at /host/tours/[id]) with toast "Package submitted for admin review".

Component contracts:
  TourCard: { pkg } -> renders cover image, name, lga, category, price, rating
  ItineraryTimeline: { items: [{ hour, title, description, location? }] } -> vertical timeline with hour offsets
  TourBookingForm: { pkg, signedIn, defaultEmail } -> renders date picker, passenger stepper, split-bill toggle, email field, submit; calls onSubmit prop with full payload
