<objective>
Build the backend-only CRUD surface for `SettlementSplitTier` (D-04: no new web admin UI this phase) — a `GET /admin/settlement-splits` list route and a `PATCH /admin/settlement-splits/:id` update route on the existing `AdminController`, both narrowed to `@Roles(UserRole.SUPER_ADMIN)` only (diverging from the controller's class-level `SUPER_ADMIN, LGA_ADMIN` default, matching the existing `getRevenue()` money-adjacent precedent). The `PATCH` handler must NOT perform a naive in-place `update()` — per D-05's "old tier rows are never deleted or overwritten" requirement, it inserts a new active row and deactivates the prior one inside a single `$transaction`.

Purpose: satisfies SETTLE-11a's "operator can view and update... without a code deploy" success criterion and SETTLE-11c's effective-dated/audit-history requirement for admin-driven changes.

Output: `UpdateSplitTierDto` (class-validator, 0-1 range), `AdminService.listSplitTiers()`/`updateSplitTier()`, two new `AdminController` routes.

This plan does NOT touch any of the 6 feature-service call sites (`18-02-PLAN.md`, `18-03-PLAN.md`) — it only depends on `18-01`'s `SettlementSplitTier` model existing, and touches disjoint admin-module files, so it runs in parallel with `18-02`/`18-03` in Wave 2.
</objective>
