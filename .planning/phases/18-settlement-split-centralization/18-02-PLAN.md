<objective>
Migrate the 3 "mechanically straightforward" settlement call sites — Transport, Delivery, Events — off duplicated inline `platformConfig.findUnique()` reads onto the new centralized `SettlementService.resolveSplit()` resolver added in `18-01-PLAN.md`. Transport and Delivery additionally require the D-03 unit conversion (0-1 fraction → whole-number percent) since their existing arithmetic expects whole numbers; Events is already fraction-shaped and needs no conversion.

Purpose: eliminates 3 of the 6 duplicated `PlatformConfig` read pairs this phase targets (SETTLE-11a/b), while proving byte-for-byte identical computed amounts before/after migration via regression tests.

Output: `transport.service.ts`, `delivery.service.ts`, `events.service.ts` each call `resolveSplit()` exactly once; their recipients arrays and `settle()` calls are untouched; each has an extended regression test proving identical output for identical input.

This plan does NOT touch Marketplace, Stays, or Studio (the 3 call sites with special-case constraints — see `18-03-PLAN.md`), nor the admin CRUD endpoints (`18-04-PLAN.md`). All three plans depend only on `18-01` and touch disjoint files, so they run in parallel in Wave 2.
</objective>
