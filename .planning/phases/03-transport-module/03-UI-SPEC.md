## Spacing Scale

Declared values (React Native — unitless numbers equal CSS px at 1× density):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4 | Icon gaps, star-rating gaps, inline padding between icon and text |
| sm | 8 | Compact internal card padding, badge padding, chip horizontal padding |
| md | 16 | Default horizontal screen padding, card internal padding |
| lg | 24 | Section separation, card margin-bottom on earnings list |
| xl | 32 | Major block vertical gaps (e.g. between map and info card) |
| 2xl | 48 | —  |
| 3xl | 64 | — |

Exceptions:
- **Go-online toggle:** minimum touch target 72 × 72 (thumb-friendly, one-handed safe). Enforced by explicit `width: 72, height: 72` on the toggle button.
- **Accept / Decline ride buttons:** minimum touch target height 56. Enforced by `paddingVertical: 16`.
- **Tab bar height:** 60 (inherited from existing `_layout.tsx` — do not change).
- **Map height (full-screen screens):** `flex: 1` — takes all available space above the info card overlay.
- **Matching countdown timer:** visible text minimum 48px font size so it reads instantly under stress.

Source: Derived from existing tab screens (16px horizontal padding, 12–16px card internal padding). Touch targets follow Apple HIG 44pt minimum; go-online elevated to 72 for safety-critical one-handed use.

## Typography

All sizes reference React Native `fontSize` (unitless — maps to sp on Android, pt on iOS at 1× scale).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14 | 400 (normal) | 1.4 | Card meta text, secondary labels, fare breakdown line items |
| Label | 13 | 700 (bold) | 1.3 | Badge text, tab bar labels (11 — from existing `_layout.tsx`, not changed), button labels |
| Heading | 24 | 700 (bold) | 1.2 | Screen headings ("Transport", "Driver", matching all existing tabs), fare totals, earnings amounts |
| Display | 48 | 700 (bold) | 1.0 | Matching countdown timer; earnings total on Driver Home; trip receipt total |

Note: `fontWeight: 'bold'` = 700 in React Native. `fontWeight: 'normal'` = 400. Two weights only — bold and normal.
Existing tabs use `fontSize: 24, fontWeight: 'bold'` for headings — this contract carries that forward.

Source: Directly extracted from `events.tsx` (`fontSize: 24` heading, `fontSize: 14` card title, `fontSize: 11` meta), `stays.tsx` (identical pattern).

## Interaction Contracts

### Real-time GPS Update (Driver Marker)
- Driver Marker position updates on every `driver:location` WebSocket event.
- Update interval from server: every 2 seconds (TRANSPORT-04).
- Client animates Marker position using `Animated.timing` with `duration: 800ms` to smooth between discrete GPS points.
- No polling fallback — if socket disconnects, display "Connection lost" inline banner (JUNGLE background, white text, full-width, below header).

### Go-Online Toggle
- Tap when offline → REST `POST /api/v1/transport/go-online` with current GPS coordinates.
- Optimistic UI update: toggle button reflects "online" state immediately; revert on API error.
- Location permission must be granted before go-online is tappable; if denied, show permission error instead.

### Match Timeout (60 seconds)
- Timer starts from the moment trip request is confirmed (`POST /transport/trips` returns 201).
- Timer is client-side display only; authoritative timeout is server-side (SchedulerRegistry).
- On WebSocket event `trip:expired`: timer stops, spinner removed, expired state shown.
- On WebSocket event `driver:matched`: timer stops, navigate to T-4 Active Trip.

### Driver Accept/Decline (15-second window)
- Timer bar depletes from right to left using `Animated.timing`.
- On `ACCEPT`: REST `PATCH /transport/trips/:id/accept`, card dismisses, driver proceeds to D-3.
- On `DECLINE`: REST `PATCH /transport/trips/:id/decline`, card dismisses, driver stays on D-1.
- On timeout (no action): card auto-dismisses, acceptance rate affected (visible in D-5).

### Surge Banner Visibility
- Always shown when `surgeMultiplier > 1.0` — both on Transport Home (T-1) and Fare Estimate (T-2).
- Banner is not dismissable — rider must see surge before confirming.
- Surge multiplier is fetched as part of the `GET /transport/fare-estimate` response — never client-computed.

### Earnings Credit Confirmation (Trip Completion)
- Driver must see the success banner ("₦{N} credited") before navigation occurs.
- Auto-navigate after 2-second delay — do not navigate before banner is rendered.
- This prevents the driver missing wallet credit confirmation (per project context constraint).

### Platform: iOS vs Android Map Provider
- `MapView` with no `provider` prop on iOS = Apple Maps (default, no API key required).
- `MapView provider="google"` on Android = Google Maps (requires `GOOGLE_MAPS_API_KEY` in app.json).
- Use `Platform.OS === 'android' ? 'google' : undefined` for the `provider` prop.
- Source: Pitfall 6 in RESEARCH.md — AirGoogleMaps iOS build failure.

## State Machine Contracts

### Rider Trip State
```
IDLE → [select vehicle + enter locations] → ESTIMATING → [confirm ride] → SEARCHING (60s timer)
SEARCHING → [driver matched] → ACTIVE_TRIP → [trip complete] → RATING → IDLE
SEARCHING → [cancel] → IDLE
SEARCHING → [60s timeout] → EXPIRED → IDLE
ACTIVE_TRIP → [cancel] → CANCEL_CONFIRMATION → IDLE
```

### Driver Shift State
```
OFFLINE → [go online, GPS granted] → ONLINE
ONLINE → [go offline] → OFFLINE_CONFIRMATION → OFFLINE
ONLINE → [ride request arrives] → RIDE_REQUEST (15s window)
RIDE_REQUEST → [accept] → PICKUP → [arrived] → IN_TRIP → [complete] → EARNINGS_CREDIT → ONLINE
RIDE_REQUEST → [decline or timeout] → ONLINE
```
