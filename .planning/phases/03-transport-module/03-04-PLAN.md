  <behavior>
    Every test in transport.service.spec.ts must pass. Specifically:

    **Driver lifecycle:**
    - `createDriver(userId, dto)`: throws ConflictException if `prisma.driver.findFirst({ where: { userId, deletedAt: null } })` returns a row; otherwise creates Driver with status PENDING_REVIEW, isOnline false, totalTrips 0, avgRating 0.
    - `approveDriver(driverId, lgaAdminId, { status, notes })`: updates driver record, sets approvedById = lgaAdminId, approvedAt = now(); throws NotFoundException if driver missing.
    - `goOnline(userId, dto)`: loads driver by userId; throws NotFoundException if missing, ForbiddenException if status !== APPROVED; calls `redis.geoadd('drivers:online', dto.lng, dto.lat, driver.id)`; sets a heartbeat key `redis.set('driver:heartbeat:'+driver.id, now, 90)`; updates driver.isOnline=true, lastSeenAt=now.
    - `goOffline(userId)`: loads driver, calls `redis.zrem('drivers:online', driver.id)`, removes heartbeat key, updates driver.isOnline=false.

    **Fare:**
    - `haversineDistanceKm(lat1, lng1, lat2, lng2)`: pure function using R=6371 km, returning distance in km.
    - `getFareEstimate(q)`: reads `transport_base_fare_<lower(vehicleType)>` and `transport_per_km_<lower(vehicleType)>` from PlatformConfig (use `prisma.platformConfig.findUnique({ where: { key } })`); computes distanceKm via haversine; computes surgeMultiplier via `this.getSurgeMultiplier(pickupLat, pickupLng)`; returns `{ baseFare, distanceKm, perKmFare, surgeMultiplier, totalFare: (baseFare + distanceKm * perKmFare) * surgeMultiplier }` rounded to 2 decimals.

    **Surge:**
    - `getSurgeMultiplier(lat, lng)`: reads `transport_surge_threshold` (default 1.5) and `transport_match_radius_km` (default 5) from PlatformConfig; supply = `redis.geosearch('drivers:online', lng, lat, radiusKm).length`; demand = `prisma.trip.count({ where: { status: { in: ['SEARCHING','MATCHED'] }, requestedAt: { gte: new Date(Date.now() - 5*60*1000) } } })`; if supply === 0 return 2.0; ratio = demand / supply; if ratio <= threshold return 1.0; else return Math.min(Math.round((ratio/threshold) * 10) / 10, 2.0).

    **Ride request + match:**
    - `requestRide(userId, dto)`: computes fare via `getFareEstimate`; creates Trip row with riderId=userId, vehicleType=dto.vehicleType, status SEARCHING, fare=totalFare, surgeMultiplier; calls `redis.geosearch('drivers:online', dto.pickupLng, dto.pickupLat, radiusKm)`; if at least one driver returned, emits `gateway.server.to('driver:'+nearestDriverId).emit('ride:request', trip)`; calls `this.scheduleMatchTimeout(trip.id)`; returns trip.
    - `scheduleMatchTimeout(tripId)`: registers `schedulerRegistry.addTimeout('match:'+tripId, setTimeout(() => this.expireUnmatchedTrip(tripId), 60_000))`.
    - `expireUnmatchedTrip(tripId)`: updates trip.status=EXPIRED if still SEARCHING; emits `gateway.server.to('trip:'+tripId).emit('trip:expired')`.
    - `acceptTrip(tripId, driverUserId)`: loads driver by userId; throws ForbiddenException if status !== APPROVED; updates trip with driverId, status MATCHED, matchedAt; cancels match timeout; emits `gateway.server.to('trip:'+tripId).emit('driver:matched', { driver, trip })`; creates TripEvent { event: 'DRIVER_MATCHED' }.
    - `declineTrip(tripId, driverUserId)`: creates a TripEvent { event: 'DRIVER_DECLINED' }; trip stays SEARCHING; service may attempt next-nearest driver in a future iteration (out of scope here — but record the decline event so acceptance rate calculation works).

    **Trip completion + earnings:**
    - `completeTrip(tripId, driverUserId)`: throws BadRequestException if trip.status !== IN_PROGRESS or driverId doesn't match; reads `transport_platform_fee_pct` from PlatformConfig (default 15); computes platformFee = fare * (pct/100) and driverEarnings = fare - platformFee (== fare * 0.85 when pct=15); generates ref = `ISY-DRV-${uuidv4().replace(/-/g,'').slice(0,12).toUpperCase()}`; runs `prisma.$transaction([ trip.update({ status: COMPLETED, completedAt, platformFee, driverEarnings }), tripEvent.create({ event: 'TRIP_COMPLETED' }) ])`; loads driver wallet via `prisma.wallet.findFirst({ where: { userId: driverUserId } })`; calls `walletService.creditWallet(driverWallet.id, driverEarnings, ref, 'Trip earnings — '+tripId, 'transport', 'INTERNAL')`.

    **Cancellation:**
    - `cancelTrip(tripId, userId)`: only the rider or matched driver can cancel; updates status to CANCELLED, sets cancelReason from dto if available; cancels match timeout; emits `trip:cancelled` to room.

    **Earnings dashboard:**
    - `getDriverEarnings(userId, period)`: loads driver; computes startDate (today midnight or 7 days ago); aggregates `prisma.trip.aggregate({ where: { driverId, status: 'COMPLETED', completedAt: { gte: startDate } }, _sum: { driverEarnings: true }, _count: true })`; computes acceptanceRate by reading TripEvent counts of DRIVER_MATCHED vs DRIVER_DECLINED for this driver; computes avgRating from driver.avgRating; returns `{ totalEarnings, tripCount, acceptanceRate, avgRating }`.

    **Background cleanup:**
    - `@Cron(CronExpression.EVERY_30_SECONDS) cleanStaleDriverHeartbeats()`: gets all members of `drivers:online` (use `redis.geosearch` with a global radius), checks each driver's heartbeat key; if missing (TTL expired), removes from geo set and updates driver.isOnline=false. Wrap in try/catch and log errors — never throw from a cron.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Controller → Service | DTOs already validated; service trusts shapes but enforces business invariants (driver status, trip status, ownership) |
| Service → Wallet | Direct in-process call; no network; same Prisma transaction context |
| Service → Redis | Untrusted data: another process could pollute drivers:online geo set; service treats Redis as advisory and re-checks driver status from Postgres before trusting |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Tampering | Driver requests fare with manipulated coordinates to inflate fare | mitigate | Fare always re-computed server-side at confirmation time using PlatformConfig rates and Haversine — client never supplies fare amount |
| T-03-13 | Elevation of Privilege | Suspended driver attempts goOnline | mitigate | `goOnline` checks `driver.status !== 'APPROVED'` → ForbiddenException; covered by spec test |
| T-03-14 | Repudiation | Driver disputes earnings amount | mitigate | TripEvent rows record DRIVER_MATCHED, TRIP_COMPLETED with timestamps; Transaction row records balanceBefore/balanceAfter + ISY-DRV-* reference + module='transport' |
| T-03-15 | Tampering | completeTrip called twice causing double-credit | mitigate | First call updates trip.status to COMPLETED inside $transaction; second call throws BadRequestException because trip.status !== IN_PROGRESS — single-credit guarantee |
| T-03-16 | Spoofing | Non-driver calls completeTrip with stolen tripId | mitigate | completeTrip enforces `trip.driverId === driver.id` derived from JWT-authenticated userId; ForbiddenException otherwise |
| T-03-17 | Information Disclosure | getDriverEarnings reveals other driver's earnings | mitigate | Filters by `driverId` derived from JWT-authenticated userId only; Prisma where clause cannot leak across drivers |
| T-03-18 | Denial of Service | Single rider spams requestRide creating many SEARCHING trips | accept | Throttler module already rate-limits to 100 req / 60s globally; phase 6 may add per-user trip-creation limits |
</threat_model>
