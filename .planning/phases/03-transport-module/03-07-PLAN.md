## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Driver mobile → Backend WS (driver:location) | Driver self-reports location; backend trusts but RedisService writes are throttled by heartbeat TTL |
| Driver mobile → Backend REST (go-online, accept, arrive, start, complete) | JWT-authenticated; @Roles(DRIVER) gate at controller |
| User → expo-location | OS-level permission required; denial gracefully blocks go-online |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-28 | Spoofing | Driver fakes GPS to appear closer to riders | accept | No anti-spoofing in Phase 3 MVP; Phase 6 will add Haversine plausibility check on consecutive positions |
| T-03-29 | Information Disclosure | Driver sees rider exact home address before accepting | accept | UI-SPEC shows pickup address on incoming-request card — necessary for accept/decline decision; no PII reduction in MVP |
| T-03-30 | Repudiation | Driver claims they never accepted a trip | mitigate | TripEvent log records DRIVER_MATCHED, DRIVER_ARRIVED, TRIP_STARTED, TRIP_COMPLETED with timestamps + driverId |
| T-03-31 | Tampering | Driver replays accept after another driver took the trip | mitigate | acceptTrip checks `trip.status === 'SEARCHING'` and `trip.driverId === null` — second accept fails with BadRequest |
| T-03-32 | Tampering | Suspended driver reactivates by clearing app data | mitigate | goOnline server-side checks driver.status === 'APPROVED' on every call — local state is advisory only |
| T-03-37 | Tampering | Driver taps Start Trip without arriving (skip pickup) | mitigate | Backend startTrip enforces `trip.status === 'ARRIVED'`; out-of-order PATCH /start returns 400; mobile CTA also gated on local `arrived` flag |
