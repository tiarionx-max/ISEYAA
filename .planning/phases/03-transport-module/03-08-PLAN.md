  <how-to-verify>
    Perform these 8 verification steps in order. After each step, mark PASS or note an issue. Two devices recommended (one for rider, one for driver) — or two simulators (iOS Simulator + Android emulator) if no physical devices available.

    **Setup (one-time):**
    1. Start backend: `npm run dev --workspace=backend` — confirm "Application is running on: http://0.0.0.0:3001" in logs
    2. In a separate terminal, start mobile: `npx expo start --workspace=mobile`
    3. Scan QR code on a real iOS phone AND a real Android phone (or open both simulators). Log in as TWO different test accounts: one with role CITIZEN/TOURIST (rider), one with role DRIVER (driver).
    4. Pre-seed the driver account: in Postgres, ensure the driver has a Driver row with status='APPROVED' (use Prisma Studio or psql: `UPDATE drivers SET status = 'APPROVED' WHERE userId = '<driver-userId>';` — Phase 5 will add real LGA_ADMIN approval flow)

    **Verification steps:**

    **STEP 1 — Tab registration (both devices):**
       Open the app. Confirm a "Transport" tab and a "Driver" tab appear in the tab bar with Car and Truck icons. Confirm tapping each tab loads its respective home screen.
       MUST MATCH: UI-SPEC.md Tab 1 / Tab 2 entries; tabs appear before profile.

    **STEP 2 — Driver goes online (driver device):**
       On the driver device, tap the large GO ONLINE circular button. Grant location permission when prompted.
       Expected: button changes to FOREST background with green border; status dot turns green; label changes to "GO\nOFFLINE"; GPS coordinates appear in backend logs (Redis GEOADD).
       MUST MATCH: UI-SPEC.md D-1 toggle states.

    **STEP 3 — Rider requests a ride (rider device):**
       On the rider device, tap Transport tab. Select "Car" vehicle type. Enter a pickup location near the driver's current GPS (within 5 km). Enter a dropoff location. Tap "Get Fare Estimate".
       Expected: Fare Estimate screen appears with map showing both pins, a polyline, fare line items, and a total in GOLD. Tap "Confirm Ride".
       MUST MATCH: UI-SPEC.md T-1 and T-2 layouts; surge banner ONLY if surgeMultiplier > 1.0.

    **STEP 4 — Driver receives request and accepts (driver device):**
       Within 60 seconds of rider confirming, the driver device should see the Incoming Request card with pickup, dropoff, distance, fare highlight, animated countdown timer (15s), and Accept/Decline buttons. Tap Accept.
       Expected: card dismisses; driver advances to D-3 Active Pickup screen with map and "I've Arrived" CTA. Rider device automatically advances from T-3 Matching to T-4 Active Trip showing the driver name + rating in the bottom card.
       MUST MATCH: UI-SPEC.md D-2 incoming-request layout, T-4 active-trip layout.

    **STEP 5 — Live GPS streaming (both devices):**
       Walk a few steps with the driver device (or change the simulator location to ~50m from the previous position).
       Expected: Within ~2 seconds, the rider device's map shows the driver Marker at the new position (smooth animated transition). The driver's own map shows their heading-arrow updating.
       MUST MATCH: UI-SPEC.md Real-time GPS Update interaction contract — "Update interval from server: every 2 seconds" + "duration: 800ms" smooth Marker animation.

    **STEP 6 — Trip completion + wallet credit (driver device):**
       On the driver device, tap "Complete Trip" → confirm in bottom sheet → wait for the green inline banner showing "₦{N} credited to your wallet."
       Expected: Banner appears for ~2 seconds; driver auto-navigates to D-5 Earnings Dashboard. Today's earnings increases by 85% of the trip fare.
       Then verify in the database: run `SELECT reference, amount, gateway, metadata FROM transactions WHERE reference LIKE 'ISY-DRV-%' ORDER BY "createdAt" DESC LIMIT 1;` — confirm a row exists with `gateway = 'INTERNAL'` and amount equals 0.85 × trip fare.
       MUST MATCH: TRANSPORT-06 success criterion + UI-SPEC.md D-4 earnings-credit-state.

    **STEP 7 — Rider rates the trip (rider device):**
       On the rider device, the T-5 Trip Complete screen should appear (driver completion broadcasts to trip room). Tap stars to rate 1–5. The "Done" button should be disabled (opacity 0.4) until a rating is selected.
       Expected: After rating + Done, rider returns to T-1 Transport Home with state cleared.
       MUST MATCH: UI-SPEC.md T-5 layout + Copywriting Contract.

    **STEP 8 — Earnings dashboard period toggle (driver device):**
       On D-5, tap "Today" then "This Week" toggle. Confirm the total updates and trip-history list re-renders. Confirm acceptance rate and avg rating values appear.
       MUST MATCH: UI-SPEC.md D-5 segmented-control + stats-row.
  </how-to-verify>
