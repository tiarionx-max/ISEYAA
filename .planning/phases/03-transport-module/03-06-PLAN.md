<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile client → Backend WebSocket | JWT in handshake.auth.token; same token used for REST; backend validates on connect |
| Mobile client → Backend REST | Bearer token via api.ts axios interceptor |
| User → Mobile (location permission) | expo-location requires foreground permission grant; rider denial blocks fare estimate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-24 | Information Disclosure | Real-time location shared with backend | mitigate | Foreground only; permission requested before geo capture; user sees system permission dialog (Apple HIG / Android) |
| T-03-25 | Tampering | Rider modifies fare in client before submission | mitigate | Mobile sends only pickup/dropoff coords + vehicleType; backend re-computes fare authoritatively (Plan 04 service) — client-supplied amount ignored |
| T-03-26 | Repudiation | Rider claims they never confirmed the ride | accept | TripEvent log + audit trail server-side; mobile UI is informational |
| T-03-27 | Spoofing | Token theft via shared device | accept | Token stored in SecureStore (hardware-backed enclave on iOS/Android); device-level threat outside Phase 3 scope |
</threat_model>
