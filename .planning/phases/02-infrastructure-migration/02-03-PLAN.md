    Create backend/src/search/search-indexer.service.ts.

    Class SearchIndexerService implements OnModuleInit:
    - private readonly logger = new Logger(SearchIndexerService.name)
    - constructor(private readonly searchService: SearchService, private readonly prisma: PrismaService)
    - async onModuleInit(): Promise<void> — entry point that orchestrates full re-index

    onModuleInit() logic (idempotency guard):
    1. Call searchService.initCollections() to ensure all 4 collections exist
    2. Check document count in each collection via searchService.getCollectionCount(collection)
    3. If ALL 4 collections have 0 documents: proceed with bulk index
    4. If ANY collection has > 0 documents: log "Typesense already indexed, skipping bulk index" and return
    5. The idempotency guard is conservative: if any collection is non-empty, assume index is valid

    Bulk index logic (runs only when all collections are empty):
    - Fetch all attractions from Prisma: prisma.attraction.findMany() — map each to { id: record.id, name: record.name, description: record.description ?? '', category: record.category ?? 'general', lga_id: record.lgaId ?? '', location: [record.latitude ?? 0, record.longitude ?? 0] }
    - Fetch all events: prisma.event.findMany() — map to { id: record.id, title: record.title, description: record.description ?? '', lga_id: record.lgaId ?? '' }
    - Fetch all properties: prisma.property.findMany() — map to { id: record.id, name: record.name, description: record.description ?? '', lga_id: record.lgaId ?? '', location: [record.latitude ?? 0, record.longitude ?? 0] }
    - Fetch all products: prisma.product.findMany() — map to { id: record.id, name: record.name, description: record.description ?? '', category: record.category ?? 'general' }

    For each collection, index documents in batches of 100 using searchService.indexDocument(). Log progress: "Indexing {count} {collection} documents into Typesense".

    Wrap entire onModuleInit() in try/catch: if Typesense is unreachable (e.g., dev environment without Typesense running), log a warning and return gracefully. DO NOT throw — a missing Typesense connection must not prevent the app from starting.

    Error handling: if a single document fails to index, log the error and continue to the next document (do not abort the entire batch).

    IMPORTANT: Read backend/prisma/schema.prisma before writing the indexer to get the exact Prisma model field names. The field mapping above uses assumed names — adjust to match actual schema field names (e.g., lgaId vs lga_id, latitude/longitude vs coordinates).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → Search API | User-supplied q, lat, lng params cross HTTP boundary |
| App → Typesense | API key crosses from Railway container to Typesense service on private network |
| Typesense Admin Key | Admin key used server-side for index management; read-only key for search |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Elevation of Privilege | Typesense admin API key exposed to frontend | mitigate | TYPESENSE_API_KEY is server-side only; create a scoped read-only search API key in Typesense for any future client-side use |
| T-02-11 | Information Disclosure | Search returns PII from indexed documents | mitigate | Collection schemas only index public fields (name, description, category); do NOT index phone, email, bvn, nin, wallet balance |
| T-02-12 | Denial of Service | No rate limiting on /api/v1/search | mitigate | Global ThrottlerGuard (100 req/60s) applies; add per-IP stricter limit in Phase 6 if needed |
| T-02-13 | Tampering | q parameter injection into Typesense query | accept | Typesense uses parameterized queries internally; raw string concatenation not used in filter_by (lat/lng are validated as numbers by DTO) |
| T-02-14 | Denial of Service | Typesense index loss on Railway restart | mitigate | Persistent volume at /data required (user_setup); SearchIndexerService.onModuleInit() re-indexes if collections are empty after restart |
</threat_model>
