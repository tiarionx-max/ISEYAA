    FILE 1: .github/workflows/check-no-env.yml

    Create a GitHub Actions workflow that fails if any .env file (other than .env.example) is committed:

      name: Security — No .env files in git
      on: [push, pull_request]

      jobs:
        check-no-env:
          runs-on: ubuntu-latest
          steps:
            - uses: actions/checkout@v4
            - name: Verify no .env files committed
              run: |
                FOUND=$(git ls-files | grep -E '\.env$|\.env\.' | grep -v '\.env\.example$' || true)
                if [ -n "$FOUND" ]; then
                  echo "ERROR: Committed .env files found:"
                  echo "$FOUND"
                  exit 1
                fi
                echo "OK: No .env files committed"

    This workflow runs on every push and PR. It uses git ls-files (only tracks committed files, not working directory) and fails if any .env or .env.* file is tracked except .env.example.

    Do NOT remove any existing .gitignore entries.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI/CD → Railway | Docker image built and pushed; Railway pulls from registry |
| Railway → Infisical | INFISICAL_TOKEN used to pull secrets at container start |
| Docker image → secrets | Container runtime receives secrets via Infisical CLI; no secrets baked into image |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-20 | Information Disclosure | Secrets baked into Docker image layers | mitigate | No ENV or ARG with secret values in Dockerfile; all secrets injected at runtime by infisical run |
| T-02-21 | Information Disclosure | .env files committed to git | mitigate | CI gate (check-no-env.yml) blocks any push with .env files; .gitignore prevents accidental add |
| T-02-22 | Spoofing | INFISICAL_TOKEN exposed in Railway service | accept | INFISICAL_TOKEN is intentionally in Railway (it is the bootstrap secret); mitigated by Infisical's machine identity scoping (read-only to iseyaa project) |
| T-02-23 | Denial of Service | Infisical CLI not found at container start | mitigate | Dockerfile installs infisical via Alpine package during build; if install fails, Docker build fails (not runtime) |
| T-02-24 | Tampering | Docker image built from dirty working directory | mitigate | .dockerignore excludes .env, node_modules, .git; CI builds from clean git checkout |
</threat_model>
