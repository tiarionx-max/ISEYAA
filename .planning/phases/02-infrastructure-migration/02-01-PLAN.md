<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App → Neon | DATABASE_URL crosses from Railway container to Neon cloud; connection string contains credentials |
| App → Upstash | REDIS_URL crosses from Railway container to Upstash; TLS URL contains password |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | DATABASE_URL / DIRECT_URL in env | mitigate | Store both URLs in Infisical only; Railway service receives INFISICAL_TOKEN, never raw DB creds; Plan 06 implements this |
| T-02-02 | Information Disclosure | REDIS_URL in env | mitigate | Same Infisical approach as T-02-01; rediss:// TLS URL encrypted in transit |
| T-02-03 | Tampering | prisma migrate against wrong branch | mitigate | DIRECT_URL must point to dev branch during development; prod branch migrations only run in CI/CD via DIRECT_URL secret per environment |
| T-02-04 | Denial of Service | Neon connection pool exhaustion | mitigate | DATABASE_URL must include ?pgbouncer=true&connection_limit=1 to prevent Prisma prepared statement conflict with PgBouncer transaction mode |
| T-02-05 | Information Disclosure | Archived migration files exposed in git | accept | Archived files contain only DDL (no data); low risk; directory name _archived_db_push makes purpose clear |
</threat_model>
