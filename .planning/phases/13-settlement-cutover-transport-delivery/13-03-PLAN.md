<objective>
Converge Delivery's `completeDelivery()` onto the generalized `SettlementService.settle()` (Phase 12), gated behind the `delivery.settlement_engine_enabled` `PlatformConfig` flag, so rider/Ministry/platform wallets are credited atomically via the shared engine post-cutover — while the pre-cutover path stays byte-for-byte unchanged and additionally records a Stage-2 shadow comparison for every real completion (SETTLE-04, SETTLE-09).

Purpose: This is the actual rider-payout cutover for Delivery, mirroring Plan 13-02's Transport cutover but preserving Delivery's distinct multiply-first rounding formula. Runs in parallel with Plan 13-02 (disjoint files, both depend only on Plan 13-01).
Output: `completeDelivery()` with a working cutover-flag branch; `delivery.service.spec.ts` covering both flag states.

Naming-convention note: `ISY-DLV-${orderId}` (this plan) is, together with Plan 13-02's `ISY-TRP-${tripId}`, a deliberate, documented deviation from CLAUDE.md's `ISY-<TYPE>-<12-char-uppercase>` reference pattern — the raw order UUID (not a random 12-char suffix) is required because `SettlementService`'s idempotency precheck (`settlement.service.ts:94-103`) needs a **stable, deterministic** reference per delivery to detect replays (13-RESEARCH.md Pitfall 2). Plan 13-02's Task 1 (step 7) appends the `CLAUDE.md` Naming Patterns documentation for BOTH this convention and its own in a single edit, since Plans 13-02/13-03 execute in the same wave (Wave 2) and both editing `CLAUDE.md` in parallel would create a same-wave file conflict. This plan therefore does not modify `CLAUDE.md` directly.
</objective>
