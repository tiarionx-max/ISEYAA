<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile UI → Backend API | Delivery order creation, fee estimate, and cancel calls go via authenticated axios (api.post/patch); JWT injected from SecureStore |
| Mobile UI → WebSocket | Socket.io connected with JWT in auth.token handshake; same pattern as transport.tsx |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-18 | Information Disclosure | OTP displayed in D-4 sender screen | accept | The OTP is shown to the sender who is the party creating the order; the recipient also receives the OTP via SMS; showing it to the sender allows verbal sharing — this is by design per DELIVERY-04 |
| T-04-19 | Spoofing | expo-image-picker camera access on iOS | mitigate | NSCameraUsageDescription and NSPhotoLibraryUsageDescription declared in app.json; permission requested at runtime before picker launches; no camera access without explicit user grant |
| T-04-20 | Elevation of Privilege | Delivery fee computed client-side and sent to confirm | accept | D-2 quote screen calls GET /fee-estimate and displays server-computed fee; POST /orders sends the fee back, but server recomputes and uses its own value — client value is not trusted per DeliveryService.requestDelivery implementation |
</threat_model>
