## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DeliveryService → Redis (geo-set) | Rider IDs are internal UUIDs; coordinates validated in DTO before reaching service |
| DeliveryService → WalletService | creditWallet called only after dual-gate (OTP + photo) passes; gateway='INTERNAL' prevents external payment bypass |
| DeliveryService → S3Service | Photo uploaded with explicit contentType='image/jpeg'; S3 key scoped to delivery-proof/ prefix |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-09 | Tampering | completeDelivery dual-gate bypass | mitigate | Service checks both `!order.otpVerifiedAt` (server-set field) AND `!dto.proofPhotoBase64` presence; mobile UI enforces both gates but backend is authoritative |
| T-04-10 | Elevation of Privilege | Wallet double-credit on delivery | mitigate | `order.status` checked before credit; order updated to DELIVERED in same prisma.$transaction as event creation; subsequent calls find status=DELIVERED and throw |
| T-04-11 | Spoofing | Unauthorized rider accepting order | mitigate | acceptOrder verifies `rider.userId === driverUserId` (rider owns the JWT) AND `rider.status === 'APPROVED'` before accepting |
| T-04-12 | Tampering | Delivery fee computed client-side | accept | Fee always computed server-side in getFeeEstimate + requestDelivery; client sends only coordinates + weightKg; server recomputes |
| T-04-13 | Tampering | Photo upload content injection | mitigate | proofPhotoBase64 decoded as Buffer; contentType hardcoded to 'image/jpeg' (not from request); S3 key prefix 'delivery-proof/' scopes writes |
</threat_model>
