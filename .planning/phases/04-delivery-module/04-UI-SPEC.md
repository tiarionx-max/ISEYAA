# Phase 4 — UI Design Contract

> Visual and interaction contract for the Delivery Module mobile screens.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Platform: React Native + Expo SDK 51 (iOS + Android). No shadcn — mobile-only.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (React Native StyleSheet — consistent with all existing tabs) |
| Preset | not applicable |
| Component library | React Native core — View, Text, TouchableOpacity, StyleSheet, ActivityIndicator, FlatList, TextInput, ScrollView, Animated |
| Map library | react-native-maps ~1.14.0 — MapView + Marker; Apple Maps on iOS (no API key), Google Maps on Android |
| Image picker | expo-image-picker (new dependency — must be added; not yet in mobile/package.json); used exclusively on R-4 for proof-of-delivery photo upload |

| Safe area | react-native-safe-area-context SafeAreaView — used on every existing tab screen |

Source: Detected from `mobile/app/(tabs)/transport.tsx`, `driver.tsx`, `_layout.tsx`. `expo-image-picker` confirmed absent from `mobile/package.json` — new install required.

## Spacing Scale

Declared values (React Native — unitless numbers equal CSS px at 1× density):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4 | Icon gaps, gap between OTP digit cells, inline spacing between icon and text |
| sm | 8 | Compact internal card padding, badge padding, chip horizontal padding |
| md | 16 | Default horizontal screen padding, card internal padding |
| lg | 24 | Section separation, card margin-bottom on earnings list |
| xl | 32 | Major block vertical gaps (e.g. between map and info card) |
| 2xl | 48 | — |
| 3xl | 64 | — |

Exceptions:
- **Go-online/offline toggle (R-1):** minimum touch target 120 × 120 — identical to Driver D-1 pattern.
- **Accept / Decline delivery buttons (R-2):** minimum touch target height 56. Enforced by `paddingVertical: 16`.
- **OTP digit cells (R-4):** each cell is 48 × 56 (`width: 48, height: 56`), `borderRadius: 10`, with `gap: 8` between cells. Six cells in a flex row.
- **Photo upload button (R-4):** minimum touch target height 80 — large enough to tap and convey the file-attachment intent. `height: 80, borderRadius: 12`.
- **Tab bar height:** iOS 80 / Android 68 (inherited from existing `_layout.tsx` — do not change).
- **Map height (full-screen screens):** `flex: 1` — takes all available space above the info card overlay.
- **Matching countdown timer:** visible text minimum 48px font size so it reads instantly under stress.

Source: Directly carried forward from Phase 3 UI-SPEC; spacing tokens identical to transport.tsx and driver.tsx implementation.

## Typography

All sizes reference React Native `fontSize` (unitless — maps to sp on Android, pt on iOS at 1× scale).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14 | 400 (normal) | 1.4 | Card meta text, secondary labels, delivery fee breakdown line items, OTP instruction text |
| Label | 13 | 700 (bold) | 1.3 | Badge text, tab bar labels (10 — from existing `_layout.tsx`, not changed), button labels, timer countdown label |
| Heading | 24 | 700 (bold) | 1.2 | Screen headings ("Delivery", "Rider", "Earnings"), delivery fee totals, earnings amounts |
| Display | 48 | 700 (bold) | 1.0 | Matching countdown timer; earnings total on R-1 and R-5; delivery receipt total |

Note: `fontWeight: 'bold'` = 700 in React Native. `fontWeight: 'normal'` = 400. Two weights only — bold and normal.
Existing tabs use `fontSize: 24, fontWeight: 'bold'` for headings — this contract carries that forward unchanged.

Source: Directly extracted from `transport.tsx` and `driver.tsx` — identical typography system.

| OTP verified state | `rgba(34,197,94,0.15)` + `#22C55E` border | OTP input cell border turns green when 6-digit code is accepted |
| OTP error state | `rgba(220,38,38,0.15)` + `#DC2626` border | OTP input cell border turns red when code is rejected |
| Rider online | `#22C55E` (green-500) | Online status dot indicator only |
| Rider offline | `#6B7280` (gray-500) | Offline status dot indicator only |
| Photo selected | `rgba(26,107,60,0.2)` background + `#22C55E` border | Photo upload button after image selected — signals completion |
| White primary | `#FFFFFF` | Primary text on dark backgrounds |
| INACTIVE | `rgba(255,255,255,0.28)` | Tab bar inactive icon/label — inherited from `_layout.tsx` |

**Accent (`#C8962A` GOLD) reserved for:**
- Active tab bar icon and label (inherited from `_layout.tsx`)
- Primary CTA buttons ("Get Delivery Quote", "Confirm Delivery", "Accept", "Confirm Delivery" on R-4)
- Delivery fee price text in quote card and receipts
- Rider earnings total figure
- Icon highlights in delivery info rows (MapPin, Navigation, Package)
- `ActivityIndicator` color (loading spinner)
- OTP display on D-4 (sender's OTP value is gold text — high contrast, draws attention)
- ETA chips on D-4 and R-3

Accent is NOT used on: body copy, secondary labels, card borders, map UI, cancel buttons, decline buttons, error states, or OTP input cells.

Source: Color tokens extracted directly from `transport.tsx` and `driver.tsx`. OTP state colors and photo upload states are new additions for this phase.

## Interaction Contracts

### Real-time GPS Update (Rider Marker on Sender Screen)
- Rider Marker position on D-4 updates on every `rider:location` WebSocket event.
- Update interval from server: every 2 seconds (mirrors TRANSPORT-04 pattern; DELIVERY-03).
- Client animates Marker position using `Animated.timing` with `duration: 800ms` to smooth between discrete GPS points.
- No polling fallback — if socket disconnects, display "Connection lost" inline banner (full-width, below header, `backgroundColor: JUNGLE`).

### Rider GPS Emission (During Active Delivery)
- Rider client emits `rider:location` event via WebSocket every 2 seconds from `Location.watchPositionAsync`.
- Emitted payload: `{ deliveryId: string, lat: number, lng: number }`.
- GPS watch starts when rider accepts delivery (R-2 → Accept) and stops when delivery is confirmed (R-4 → Confirm Delivery).

### Go-Online Toggle (R-1)
- Tap when offline → REST `POST /api/v1/delivery/go-online` with current GPS coordinates.
- Optimistic UI update: toggle reflects "online" state immediately; revert on API error.
- Location permission must be granted before go-online is tappable; if denied, show permission error alert.

### Match Timeout (60 seconds)
- Timer starts from the moment delivery request is confirmed (`POST /delivery/orders` returns 201).
- Timer is client-side display only; authoritative timeout is server-side.
- On WebSocket event `delivery:expired`: timer stops, spinner removed, expired state shown.
- On WebSocket event `rider:assigned`: timer stops, navigate to D-4 Active Delivery.

### Rider Accept/Decline (15-second window)
- Timer bar depletes from right to left using `Animated.timing`.
- On ACCEPT: REST `PATCH /delivery/orders/:id/accept`, card dismisses, rider proceeds to R-3.
- On DECLINE: REST `PATCH /delivery/orders/:id/decline`, card dismisses, rider stays on R-1.
- On timeout (no action): card auto-dismisses, acceptance rate affected (visible in R-5).

### Proximity Gate (200m) — R-3 and R-4
- Both "I've Collected" (R-3) and OTP/photo form sub-state B visibility (R-4) gate on `haversineKm(riderLat, riderLng, targetLat, targetLng) * 1000 <= 200`.
- Haversine calculation runs client-side using GPS from `Location.watchPositionAsync`.
- When outside 200m: CTA is disabled (`opacity: 0.4`, `disabled: true`), copy says "Approach pickup point" (R-3) or OTP form is hidden behind the Sub-state A prompt (R-4).
- When inside 200m: CTA activates immediately without requiring a separate tap.

### OTP Verification Flow (R-4 Sub-state B)
- OTP is a 6-digit code sent via SMS (Termii) to the recipient's phone number at the time the delivery order is created.
- Rider's flow: recipient reads the OTP aloud → rider types it into the 6-cell input.
- Input behavior: each cell `TextInput` has `maxLength: 1`. On digit entry, focus auto-advances to the next cell using `useRef` array and `focus()`. On backspace in an empty cell, focus retreats to the previous cell.
- When all 6 digits are entered: client automatically calls `POST /delivery/orders/:id/verify-otp` with `{ otp: "123456" }`.
- On success (200): OTP cells render in verified state (green border). Photo upload button becomes active.
- On failure (400/422): OTP cells render in error state (red border). Error copy shown. Cells are cleared for re-entry.
- `Confirm Delivery` CTA is only enabled when BOTH conditions are true: OTP server-verified AND photo selected (`photoUri !== null`).

### Photo Proof Upload (R-4 Sub-state B)
- Tap photo button → `expo-image-picker` `launchImageLibraryAsync` with options: `mediaTypes: ImagePicker.MediaTypeOptions.Images, allowsEditing: true, aspect: [4,3], quality: 0.7`.
- Also offer camera: long-press or secondary tap shows an Alert with two options: "Take Photo" (`launchCameraAsync`) and "Choose from Library" (`launchImageLibraryAsync`).
- Selected image URI stored in state (`photoUri: string | null`).
- Photo is uploaded to S3/R2 as part of the `PATCH /delivery/orders/:id/complete` payload (multipart or base64 — implementation choice; spec-layer only requires `photoUri` sent to backend).
- Upload progress is not shown — the Confirm Delivery CTA shows `ActivityIndicator` during the upload.

### Earnings Credit Confirmation (Delivery Completion)
- Rider must see the credit banner ("₦{N} credited") before navigation occurs.
- Auto-navigate after 2-second delay — identical to Transport D-4 pattern.
- Prevents rider missing wallet credit confirmation.

### Platform: iOS vs Android Map Provider
- `MapView` with no `provider` prop on iOS = Apple Maps (default, no API key required).
- `MapView provider="google"` on Android = Google Maps (requires `GOOGLE_MAPS_API_KEY` in app.json).
- Use `Platform.OS === 'android' ? 'google' : undefined` for the `provider` prop.
- Identical to Transport phase pattern — no change.

### Tab Bar with 8 Tabs
- Adding Delivery and Rider tabs brings the total to 9 tabs (Explore, Events, Stays, Studio, Transport, Driver, Delivery, Rider, Profile).
- The existing `_layout.tsx` `tabBarLabelStyle` uses `fontSize: 10` — compact enough to accommodate the additional tabs.
- Tab bar height remains iOS 80 / Android 68. No scrolling tab bar — Expo Tabs does not support it natively. All tabs remain visible.
- Icon sizes remain 22 from existing `TabIcon` component. Do not change `_layout.tsx` height or label size.
- New icons: `Package` (lucide-react-native) for Delivery tab, `Bike` (lucide-react-native) for Rider tab. Both are already available in lucide-react-native.

## State Machine Contracts

### Sender Delivery State
```
IDLE → [fill form] → QUOTED → [confirm delivery] → SEARCHING (60s timer)
SEARCHING → [rider assigned] → ACTIVE_DELIVERY (Picking Up → In Transit → Delivered)
SEARCHING → [cancel] → IDLE
SEARCHING → [60s timeout] → EXPIRED → IDLE
ACTIVE_DELIVERY → [cancel] → CANCEL_CONFIRMATION → IDLE
ACTIVE_DELIVERY → [rider delivers + OTP + photo confirmed] → COMPLETE → RATING → IDLE
```

### Rider Delivery Shift State
```
OFFLINE → [go online, GPS granted] → ONLINE
ONLINE → [go offline] → OFFLINE_CONFIRMATION → OFFLINE
ONLINE → [delivery request arrives] → DELIVERY_REQUEST (15s window)
DELIVERY_REQUEST → [accept] → PICKUP_NAV → [within 200m + I've Collected] → DELIVERY_NAV
DELIVERY_REQUEST → [decline or timeout] → ONLINE
DELIVERY_NAV → [within 200m + OTP verified + photo selected + confirm] → EARNINGS_CREDIT → ONLINE
```

### OTP Sub-State (R-4 Sub-state B)
```
OTP_IDLE → [6 digits entered] → OTP_VERIFYING (API call)
OTP_VERIFYING → [200 success] → OTP_VERIFIED (green cells)
OTP_VERIFYING → [error] → OTP_ERROR (red cells, cleared) → OTP_IDLE
OTP_VERIFIED + PHOTO_SELECTED → [confirm CTA enabled]
```
