**Researched:** 2026-05-16
**Domain:** AI streaming (Anthropic Claude), Upstash Vector, KYC identity verification (Nigeria), AES-256-GCM encryption, SSE in Expo React Native
**Confidence:** HIGH (core stack, Claude tool use, Upstash), MEDIUM (KYC APIs), LOW (Smile Identity Expo 51 compat)

## Summary

Phase 5 extends the existing Claude-powered AI service with tool-calling capabilities and vector-powered recommendations, adds a three-tier KYC flow (BVN → ₦200K, NIN → ₦1M, Smile Identity liveness → ₦5M), and delivers a mobile AI Chat screen plus KYC screen.

The most important architectural decision is **model continuity**: `ai.service.ts` already uses `claude-sonnet-4-20250514` via `@anthropic-ai/sdk`. The "GPT-4o" phrasing in the phase description is a product requirement misread — the codebase is already committed to Claude and `@anthropic-ai/sdk` 0.52.x is installed. Phase 5 upgrades Claude from single-turn chat to multi-turn agentic streaming with tool calls, which `@anthropic-ai/sdk` supports natively via `messages.stream()` + `tool_use` blocks.

Upstash Vector (already listed as a Phase 2 dependency) uses its built-in embedding models so no external embedding API key is needed. The `@upstash/vector` SDK is installed via `npm install @upstash/vector` and uses `data:` field (text string) on upsert/query for automatic embedding — no raw vectors required.

KYC API: Paystack's `resolve_bvn` endpoint provides BVN verification. NIN verification is not directly available as a standalone Paystack REST endpoint; Paystack's `Validate Customer` feature covers BVN-to-account matching for dedicated virtual accounts, not bare NIN lookup. For NIN, the recommended MVP approach is **Dojah** (REST API, covers BVN + NIN, well-documented for Nigerian fintechs) or a stub with `kycStatus: PENDING` that an admin manually approves. AES-256-GCM + bcrypt-hash pattern is confirmed via Node.js built-in `crypto` module — no new npm package needed.

SSE on Expo SDK 51 / React Native 0.74: `EventSource` is not available in the React Native runtime. The recommended approach is `react-native-sse@1.2.1` which uses `XMLHttpRequest` internally and works without native modules. The existing codebase streaming pattern (`res.write + res.end` with `text/event-stream` headers) is already correct on the backend.

**Primary recommendation:** Keep Claude as the AI backend (do not switch to OpenAI), implement tool calls using Claude's `tool_use` agentic loop, use Upstash Vector with BAAI/bge-m3 auto-embedding, use Paystack for BVN + Dojah stub for NIN, AES-256-GCM via `node:crypto`, and `react-native-sse` for mobile streaming.

### Pattern 1: Claude Agentic Loop in Single SSE Connection

**What:** Tools are defined as a `tools` array in the Claude API call. When Claude emits a `tool_use` block, the service executes the tool (Prisma query) and continues the stream by sending a new request with `tool_result`. All of this happens server-side within one HTTP SSE response.

**When to use:** Any chat turn that might require live data lookups.

```typescript
// Source: [VERIFIED: platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls]
// Pattern for NestJS ai.service.ts — simplified

private readonly TOOLS = [
  {
    name: 'get_attractions',
    description: 'Find tourist attractions in Ogun State. Use when user asks about places to visit, sightseeing, or tourism.',
    input_schema: {
      type: 'object',
      properties: {
        lgaSlug: { type: 'string', description: 'LGA slug, e.g. abeokuta-south' },
        category: { type: 'string', enum: ['NATURAL','CULTURAL','HISTORICAL','RECREATIONAL','RELIGIOUS'] },
        limit: { type: 'number', description: 'Max results, default 5' },
      },
      required: ['lgaSlug'],
    },
  },
  // ... get_events, get_stays, get_ride_estimate, get_weather
];

async streamChatWithTools(userId: string, messages: any[], res: Response) {
  // Send initial SSE headers (already done in controller before calling this)
  const messageHistory = [...messages];

  // Agentic loop — max 3 tool turns to avoid infinite loops
  for (let turn = 0; turn < 3; turn++) {
    const stream = await this.anthropic.messages.stream({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 1024,
      system: this.buildSystemPrompt(),
      tools: this.TOOLS,
      messages: messageHistory,
    });

    let toolUseBlocks: any[] = [];
    let textAccumulated = '';

    for await (const chunk of stream) {
      if (chunk.type === 'content_block_delta' && chunk.delta.type === 'text_delta') {
        textAccumulated += chunk.delta.text;
        res.write(`data: ${JSON.stringify({ text: chunk.delta.text })}\n\n`);
      }
      if (chunk.type === 'content_block_start' && chunk.content_block?.type === 'tool_use') {
        toolUseBlocks.push(chunk.content_block);
      }
      // Accumulate tool_use input_json_delta into toolUseBlocks[last].input
    }

    const finalMessage = await stream.finalMessage();

    if (finalMessage.stop_reason === 'end_turn') {
      res.write('data: [DONE]\n\n');
      res.end();
      return;
    }

    if (finalMessage.stop_reason === 'tool_use') {
      // Execute all tool calls, collect results
      const toolResults = await Promise.all(
        finalMessage.content
          .filter(b => b.type === 'tool_use')
          .map(async (block: any) => ({
            type: 'tool_result' as const,
            tool_use_id: block.id,
            content: await this.executeTool(block.name, block.input),
          }))
      );

      // Emit tool cards to mobile
      for (const result of toolResults) {
        res.write(`data: ${JSON.stringify({ tool: result.tool_use_id, result: result.content })}\n\n`);
      }

      // Continue conversation with tool results
      messageHistory.push({ role: 'assistant', content: finalMessage.content });
      messageHistory.push({ role: 'user', content: toolResults });
    }
  }

  res.write('data: [DONE]\n\n');
  res.end();
}
```

### Pattern 2: Upstash Vector Interaction Tracking

**What:** After each chat turn, upsert the interaction as a text embedding. Before generating AI response, query top-K similar past interactions to personalise the system prompt.

```typescript
// Source: [VERIFIED: upstash.com/docs/vector/sdks/ts/commands/upsert]
// Source: [VERIFIED: upstash.com/docs/vector/sdks/ts/commands/query]
import { Index } from '@upstash/vector';

@Injectable()
export class VectorService {
  private index: Index;

  constructor(private config: ConfigService) {
    this.index = new Index({
      url: config.get('UPSTASH_VECTOR_REST_URL'),
      token: config.get('UPSTASH_VECTOR_REST_TOKEN'),
    });
  }

  async upsertInteraction(userId: string, message: string, response: string) {
    await this.index.upsert({
      id: `${userId}-${Date.now()}`,
      data: `User: ${message}\nAI: ${response.slice(0, 200)}`, // text → auto-embedding
      metadata: { userId, timestamp: Date.now(), type: 'chat' },
    });
  }

  async getPersonalisedContext(userId: string, currentMessage: string): Promise<string> {
    const results = await this.index.query({
      data: currentMessage,        // text → auto-embedding for query
      topK: 5,
      filter: `userId = '${userId}'`,
      includeMetadata: true,
    });
    // Returns similarity score 0–1, use scores > 0.7
    return results
      .filter(r => r.score > 0.7)
      .map(r => (r.metadata as any)?.summary ?? '')
      .join('\n');
  }
}
```

**Index configuration:** Create Upstash Vector index with `BAAI/bge-m3` model (1024 dimensions, multilingual, handles English + Yoruba). Use the `data:` field for automatic embedding — do NOT pre-compute embeddings externally. [VERIFIED: upstash.com/docs/vector/features/embeddingmodels]

### Pattern 3: AES-256-GCM PII Encryption

**What:** Encrypt BVN/NIN string using AES-256-GCM; store encrypted value in `User.bvn`/`User.nin` columns. Also store a bcrypt hash in a separate column for duplicate lookup (to reject re-verification attempts). The encrypted value can be decrypted for KYC display; the bcrypt hash is used to check `bcrypt.compare(submittedBvn, storedHash)` to prevent duplicate submissions.

```typescript
// Source: [VERIFIED: nodejs.org/api/crypto.html] + [CITED: gist.github.com/rjz/15baffeab434b8125ca4d783f4116d81]
import * as crypto from 'node:crypto';

const ALGORITHM = 'aes-256-gcm';
const IV_LENGTH = 12; // 96 bits recommended for GCM

@Injectable()
export class EncryptionService {
  private readonly key: Buffer;

  constructor(private config: ConfigService) {
    // KEY must be exactly 32 bytes (256 bits). Store as hex in env.
    const keyHex = config.get<string>('ENCRYPTION_KEY');
    if (!keyHex || keyHex.length !== 64) {
      throw new Error('ENCRYPTION_KEY must be 64 hex chars (32 bytes)');
    }
    this.key = Buffer.from(keyHex, 'hex');
  }

  encrypt(plaintext: string): string {
    const iv = crypto.randomBytes(IV_LENGTH);
    const cipher = crypto.createCipheriv(ALGORITHM, this.key, iv);
    const encrypted = Buffer.concat([
      cipher.update(plaintext, 'utf8'),
      cipher.final(),
    ]);
    const authTag = cipher.getAuthTag();
    // Store as: iv_hex:authTag_hex:ciphertext_hex
    return `${iv.toString('hex')}:${authTag.toString('hex')}:${encrypted.toString('hex')}`;
  }

  decrypt(stored: string): string {
    const [ivHex, authTagHex, ciphertextHex] = stored.split(':');
    const iv = Buffer.from(ivHex, 'hex');
    const authTag = Buffer.from(authTagHex, 'hex');
    const ciphertext = Buffer.from(ciphertextHex, 'hex');
    const decipher = crypto.createDecipheriv(ALGORITHM, this.key, iv);
    decipher.setAuthTag(authTag);
    return decipher.update(ciphertext).toString('utf8') + decipher.final('utf8');
  }
}
```

**Lookup pattern:** To prevent the same BVN being registered twice, before storing, check `User.bvnHash` via `bcrypt.compare(submittedBvn, existingHash)`. The `User.bvn` column stores the AES-GCM ciphertext (unique by IV so it cannot be used for equality lookup). ### Pattern 4: Mobile SSE Consumption with react-native-sse

**What:** `EventSource` does not exist in React Native. `react-native-sse` provides a compatible implementation using `XMLHttpRequest`. Expo SDK 51's known SSE debug-mode bug (CdpInterceptor) was resolved in SDK 50.x patch (PR #30062). SDK 51 is unaffected in release builds and patched in debug.

```typescript
// Source: [VERIFIED: npmjs.com/package/react-native-sse]
import EventSource from 'react-native-sse';
import * as SecureStore from 'expo-secure-store';

async function streamChatMessage(message: string, onChunk: (text: string) => void, onDone: () => void) {
  const token = await SecureStore.getItemAsync('access_token');
  const API_BASE = process.env.EXPO_PUBLIC_API_URL ?? 'http://localhost:3001/api/v1';

  const es = new EventSource(`${API_BASE}/ai/chat`, {
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json',
    },
    method: 'POST',
    body: JSON.stringify({ message }),
  });

  es.addEventListener('message', (event) => {
    if (event.data === '[DONE]') {
      onDone();
      es.close();
      return;
    }
    try {
      const parsed = JSON.parse(event.data);
      if (parsed.text) onChunk(parsed.text);
    } catch { /* ignore malformed */ }
  });

  es.addEventListener('error', () => {
    onDone(); // triggers error state in UI
    es.close();
  });

  return es; // caller can call es.close() to abort
}
```

**Alternative (fetch + ReadableStream):** React Native 0.74 supports `fetch` with `ReadableStream`, but this approach requires manual SSE parsing (splitting on `\n\n`, parsing `data:` prefix) and is more fragile. Prefer `react-native-sse` for maintainability. [ASSUMED: RN 0.74 ReadableStream status based on training knowledge; react-native-sse is the verified safer choice]

### Pattern 5: Wallet Tier Update on KYC Completion

**What:** KYC tier limits are currently hardcoded in `wallet.service.ts` (KYC_TIER_1_LIMIT = 50,000 / KYC_TIER_2_LIMIT = 500,000). Phase 5 adds three named tiers (BVN, NIN, Liveness) with different limits. Per CLAUDE.md: "Platform fee source: Always from DB (platformConfig table), never hardcoded."

**Decision:** Migrate wallet tier limits from hardcoded constants to `PlatformConfig` table. Keys:
- `wallet.tier.bvn_limit` = 200000
- `wallet.tier.nin_limit` = 1000000
- `wallet.tier.liveness_limit` = 5000000
- `wallet.tier.phone_limit` = 50000 (existing tier 1)

The `getKycTier()` function in `wallet.service.ts` must be replaced with an async version that reads from `PlatformConfig`. [VERIFIED: PlatformConfig model exists in schema.prisma line 565]

```typescript
type KycTierResult = { tier: 0 | 1 | 2 | 3; dailyLimitNgn: number };

async function getKycTierFromConfig(user: User, prisma: PrismaService): Promise<KycTierResult> {
  const configs = await prisma.platformConfig.findMany({
    where: { key: { in: ['wallet.tier.phone_limit','wallet.tier.bvn_limit','wallet.tier.nin_limit','wallet.tier.liveness_limit'] } }

  const limit = (key: string) => Number((configs.find(c => c.key === key)?.value as any) ?? 0);

  if (user.kycLivenessVerifiedAt) return { tier: 3, dailyLimitNgn: limit('wallet.tier.liveness_limit') };
  if (user.kycNinVerifiedAt)      return { tier: 2, dailyLimitNgn: limit('wallet.tier.nin_limit') };
  if (user.kycBvnVerifiedAt)      return { tier: 1, dailyLimitNgn: limit('wallet.tier.bvn_limit') };
  if (user.phone)                  return { tier: 0, dailyLimitNgn: limit('wallet.tier.phone_limit') };
  return { tier: 0, dailyLimitNgn: 0 };
}
```

### Anti-Patterns to Avoid

- **Single-turn Claude calls for tool use:** Do not use `messages.create()` for the agentic loop. Only `messages.stream()` should be used so partial tokens reach the client before tool execution.
- **Storing BVN/NIN in plain text in any log or response:** Ensure AES-GCM ciphertext is the only form written to Prisma. Never log the plaintext value.
- **Polling with no cap:** The mobile KYC polling for `PENDING → VERIFIED` (5s × 10 = 50s max) must have a hard ceiling and graceful fallback. See UI-SPEC line 562-566.
- **EventSource from web:** Do not use the browser `EventSource` API in mobile code. It does not exist in React Native.
- **Hardcoding wallet tier limits:** CLAUDE.md explicitly forbids hardcoding. All limits must come from `PlatformConfig` table.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Vector similarity search | Custom HNSW/cosine distance | `@upstash/vector` | Serverless, no infra to manage; handles embedding model, indexing, and ANN search |
| Authenticated encryption | Custom XOR/CBC | `node:crypto` AES-256-GCM | GCM provides both confidentiality + auth tag; CBC without MAC is vulnerable to padding oracle attacks |
| SSE in React Native | Manual `fetch` ReadableStream parsing | `react-native-sse` | Handles reconnection, header injection, POST body support — all edge cases pre-solved |
| BVN verification logic | CBN NIBSS direct integration | Paystack `/bank/resolve_bvn` | Paystack already has CBN-compliant NIBSS agreement; direct NIBSS access requires separate licensing |
| AI function routing | Manual string matching on Claude response | Claude `tool_use` + `stop_reason` | Structured JSON tool calls are reliable; string parsing on LLM output is brittle |
| Liveness detection | Camera + face detection from scratch | `@smile_identity/react-native-expo` | ISO 30107-3 compliant passive liveness; regulatory requirement for Nigerian fintech |

### NIN Verification — Dojah (RECOMMENDED for MVP)

Paystack does not expose a bare NIN lookup endpoint (only accepts NIN slip as a document type for business compliance, not a programmatic API). Dojah provides:

**Endpoint:** `GET https://api.dojah.io/api/v1/kyc/nin`
**Headers:** `AppId: ...`, `Authorization: Bearer sk_prod_...`
**Body:** `{ "nin": "12345678901" }`
**Response:** Returns `first_name`, `last_name`, `dob`, `photo`, `gender` if NIN is valid.

## AES-256-GCM + bcrypt Hash Pattern for PII Storage

The CLAUDE.md requirement: "Nigerian citizen PII (BVN, NIN) must be encrypted AES-256-GCM at rest; bcrypt hash for lookup."

**Interpretation:** Two fields per identifier:
1. `User.bvn` (String?) = AES-256-GCM ciphertext. Used to decrypt and display/verify the BVN in admin tools or KYC audit. Cannot be used for equality lookup (IV is random each encryption).
2. `User.bvnHash` (String?) = `bcrypt.hash(bvn, 12)`. Used to check `bcrypt.compare(submitted, stored)` to detect duplicate BVN registration attempts.

**New `ENCRYPTION_KEY` env var required:** 32 random bytes stored as 64 hex characters. Generate with: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.

**Storage on KYC verification:**
```typescript
// In users.service.ts verifyBvn()
const encrypted = this.encryptionService.encrypt(dto.bvn);
const hash = await bcrypt.hash(dto.bvn, 12);
await this.prisma.user.update({
  where: { id: userId },
  data: {
    bvn: encrypted,
    bvnHash: hash,
    kycBvnVerifiedAt: new Date(),
  },
});
```

**Duplicate check before verification:**
```typescript
// Check for duplicate BVN across all users (requires scanning bvnHash)
// NOTE: This is O(n) scan — acceptable for MVP scale (<100K users)
// For scale: consider storing bcrypt hash in a separate indexed table
const existingUsers = await this.prisma.user.findMany({
  where: { bvnHash: { not: null }, id: { not: userId } },
  select: { id: true, bvnHash: true },
});
for (const u of existingUsers) {
  if (await bcrypt.compare(dto.bvn, u.bvnHash!)) {
    throw new ConflictException('BVN already registered to another account');
  }
}
```

**NDPA right-to-erasure:** `users.service.ts` `eraseData()` already sets `bvn: null`. The new `bvnHash` and `ninHash` fields must also be nulled in this method.

## Common Pitfalls

### Pitfall 1: Claude Streaming with tool_use — Incomplete Input Accumulation

**What goes wrong:** During streaming, `tool_use` block inputs arrive as `input_json_delta` events. If the service only listens for `content_block_start` events and ignores `input_json_delta`, tool input will be empty/null when execution is attempted.

**Why it happens:** Claude streams tool inputs incrementally (can be hundreds of tokens for complex parameters). The full input is only available after `content_block_stop`.

**How to avoid:** Use `stream.finalMessage()` after the stream loop completes. This gives the fully assembled message including complete tool_use inputs. Do NOT try to reconstruct inputs from deltas manually.

**Warning signs:** Tool execution called with `undefined` or empty `input` object.

### Pitfall 2: AES-256-GCM Auth Tag Discarded

**What goes wrong:** GCM provides authenticated encryption — the auth tag proves the ciphertext wasn't tampered with. If the auth tag is not stored alongside the ciphertext, decryption will produce garbage without erroring.

**Why it happens:** Developers treat GCM like CBC and only store `iv:ciphertext`.

**How to avoid:** Storage format must be `iv_hex:authTag_hex:ciphertext_hex` (three colon-separated parts). `decipher.setAuthTag(authTag)` must be called before `decipher.update()`.

**Warning signs:** Decryption returns garbled text without throwing an error.

### Pitfall 3: react-native-sse POST Body Not Supported in All Versions

**What goes wrong:** Older versions of `react-native-sse` do not support `method: 'POST'` or custom `body`. The package added POST support in 1.0.0+.

**Why it happens:** The standard `EventSource` web API is GET-only. react-native-sse extended it but some docs show GET-only examples.

**How to avoid:** Use `react-native-sse@1.2.1` which supports `method`, `body`, and `headers` options. Verify by checking that `body` option is accepted without TypeScript error after install.

**Warning signs:** SSE connection opens but sends no message body; backend receives empty `body.message`.

### Pitfall 4: Upstash Vector Index Dimension Mismatch on Upsert

**What goes wrong:** Upstash Vector index is created with a fixed dimension (e.g., 384 for bge-small). If the service later switches to a different model (e.g., bge-m3 = 1024 dims), all subsequent upserts fail with dimension mismatch error.

**Why it happens:** The index dimension is set at creation time and cannot be changed without deleting the index.

**How to avoid:** Create the Upstash Vector index with `BAAI/bge-m3` (1024 dimensions, multilingual) from the start. bge-m3 handles both English and Yoruba content.

**Warning signs:** `Dimension mismatch: expected X, got Y` error on upsert.

### Pitfall 5: bcrypt Scan for Duplicate BVN is O(n)

**What goes wrong:** Checking for duplicate BVN registration requires comparing the submitted BVN against all stored bcrypt hashes (bcrypt is one-way; you cannot reverse it). At scale, this is slow.

**Why it happens:** bcrypt cannot be used for indexed equality lookup — each hash has a different salt.

**How to avoid:** For MVP scale (< 100K users), the O(n) scan is acceptable (< 200ms). For production scale, add a separate `bvnIndex` column storing `SHA-256(bvn)` (fast lookup) and keep `bvnHash` for verification. Tag as a future optimization.

**Warning signs:** KYC verification endpoint taking > 500ms as user base grows.

### Pitfall 6: Smile Identity Requires Development Build (Expo 51)

**What goes wrong:** `@smile_identity/react-native-expo` includes native modules (camera access, face detection). Expo Go does not bundle third-party native modules.

**Why it happens:** Expo Go has a fixed set of bundled native modules; Smile Identity is not included.

**How to avoid:** Use `expo run:ios` / `expo run:android` or EAS Build for any testing of Tier 3 KYC. The KYC screen should gracefully degrade if SDK is not available (show "Upgrade to access liveness verification" for Expo Go environments).

**Warning signs:** `Native module SmileID is not available` error in Expo Go.
