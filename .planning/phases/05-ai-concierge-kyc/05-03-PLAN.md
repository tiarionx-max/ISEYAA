       private async ensureNoDuplicateHash(field: 'bvnHash' | 'ninHash', plaintext: string, userId: string) {
         const others = await this.prisma.user.findMany({
           where: { [field]: { not: null }, id: { not: userId } },
           select: { id: true, [field]: true } as any,
         });
         for (const u of others) {

           if (stored && await bcrypt.compare(plaintext, stored)) {

| Service → Logs | Plaintext PII MUST NOT cross this boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-09 | Information Disclosure | BVN/NIN in HTTP error response | mitigate | Only ConflictException/BadRequestException are thrown — exception messages never include the input value (verified by test) |
| T-05-10 | Spoofing | Replay BVN verification with different userId | mitigate | userId comes from JWT (@CurrentUser); bvnHash duplicate check rejects re-registration; AuditLog records every verification |
| T-05-11 | Tampering | Direct DB write of fake kycBvnVerifiedAt | accept | Database access is service-only; admin endpoints in a different phase will audit-log changes |
| T-05-12 | Elevation of Privilege | User self-promoting to tier 3 via /kyc/smile/complete without real liveness | mitigate (partial) | MVP stub allows this when SMILE_IDENTITY env vars absent — explicitly flagged in audit log as stub mode; production requires Smile Identity webhook confirmation (Wave 7 checkpoint enforces real config) |
| T-05-13 | Information Disclosure | BVN/NIN leak via Prisma query logger | mitigate | Prisma client default does not log values; CommonModule services only log userId; CI grep gate verifies no plaintext PII in log lines |
| T-05-14 | Denial of Service | O(n) bcrypt scan for duplicate detection | accept | Acceptable for <100K users per RESEARCH Pitfall 5; flagged for SHA-256 index in Phase 6 if scale demands |
