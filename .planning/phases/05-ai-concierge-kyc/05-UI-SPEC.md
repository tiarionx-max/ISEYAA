#### Streaming text rendering

When an SSE chunk arrives (`data: {"text": "..."}`) the AI message text is updated in-place on the existing message object — never by appending a new bubble per token.

```typescript
// onChunk callback pattern (to be implemented in ai-chat.tsx)
const onChunk = useCallback((text: string) => {
  setMessages(prev => {
    const last = prev[prev.length - 1];
    if (last?.role === 'assistant' && last.streaming) {
      // Append to existing streaming message
      return [...prev.slice(0, -1), { ...last, content: last.content + text }];
    }
    // Create new streaming message
    return [...prev, { id: uuid(), role: 'assistant', content: text, streaming: true, timestamp: Date.now() }];
  });
}, []);

const onDone = useCallback(() => {
  setMessages(prev => {
    const last = prev[prev.length - 1];
    if (last?.streaming) {
      return [...prev.slice(0, -1), { ...last, streaming: false }];
    }
    return prev;
  });
  setIsStreaming(false);
}, []);
```

SSE termination signal: `data: [DONE]\n\n` triggers `onDone()`.

## Interaction States

### AI Chat — complete state machine

| State | Input bar | Send button | Message list | Typing indicator |
|-------|-----------|-------------|--------------|-----------------|
| idle (empty) | enabled, placeholder | disabled (empty) | empty state | hidden |
| idle (has text) | enabled | enabled | messages | hidden |
| streaming | disabled (editable=false) | disabled | messages + partial AI bubble | shown |
| error | enabled | enabled (retry possible) | error bubble shown | hidden |

### KYC — tier state transitions

```
LOCKED → ACTIVE (when previous tier VERIFIED)
ACTIVE → PENDING (on form submit)
PENDING → VERIFIED (on API success callback / polling)
PENDING → ACTIVE (on API error — revert so user can retry)
```

Polling interval for PENDING → VERIFIED: 5 seconds, maximum 10 attempts.
After 10 failed polls: revert to `ACTIVE` state, show error copy: "Verification is taking longer than expected. We'll notify you when complete."

## Quality Dimensions

### Dimension 1 — Copywriting
All copy declared explicitly. Primary CTAs use specific verb + noun ("Verify BVN", "Start Liveness Check", "Send message"). Empty state includes a next step. Error states include problem description + resolution path. No placeholder copy.

### Dimension 2 — Visuals
Every visual element is specified: background colors, bubble shapes, border radii, icon sizes, badge dimensions, progress bar height, input container styling. No "figure this out later" elements.

### Dimension 3 — Color
Three-color palette strictly maintained (FOREST/GOLD/JUNGLE). 60/30/10 split declared. Accent (GOLD) reserved for explicit list of elements only. Semantic values (success green #22C55E, destructive red #DC2626) introduced only for status meanings, not decoration.
