<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser session → `/admin/ministry` client-side role check | UX convenience only — the real enforcement is the backend `RolesGuard` (Plan 14-03/14-06/14-07); this page's redirect logic must never be treated as the security boundary |
| Export button → blob download | Client-triggered file download of server-rendered CSV/PDF; no client-side data transformation occurs, avoiding any client-side PII-shaping risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-16 | Elevation of Privilege | Client-side-only role gating mistaken for the actual access boundary | accept (with mitigation noted) | The page's `ALLOWED_ROLES` + `redirect()` check is UX-only; actual enforcement is the backend `@Roles(UserRole.MINISTRY_VIEWER, ...)` guard on every route this page calls (Plans 14-03/14-06/14-07) — a user bypassing the client-side redirect (e.g. via direct API calls) still hits the server-side guard and gets a 403, per RESEARCH.md's explicit anti-pattern warning |
| T-14-17 | Information Disclosure | Raw error messages/stack traces surfaced to a `MINISTRY_VIEWER` on a failed query | mitigate | Error state renders the fixed Copywriting Contract strings ("Couldn't load dashboard data." / "Check your connection and try again.") — never `error.message` or a raw API error body |
