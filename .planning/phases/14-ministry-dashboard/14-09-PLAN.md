<objective>
Fix CR-01: the Ministry dashboard's `to` date-range filter is implemented as `visitedAt <= new Date(to)` (and, independently, `createdAt <= new Date(to)` in `getRevenueToGovernment()`), where `to` is a date-only string (e.g. `"2026-07-18"`) that `new Date()` parses to UTC midnight. This silently drops almost the entire final day of every requested range — including "today" on the dashboard's own default view (`defaultDateRange()` sets `to = today`). This is a gap-closure fix for a BLOCKER-severity defect confirmed unfixed by both `14-REVIEW.md` (CR-01) and `14-VERIFICATION.md` (gap 1) against the already-executed, otherwise-verified Phase 14 codebase.

Purpose: Restore correctness of the 3 core Ministry aggregate reports (visitor entries, purpose breakdown, revenue-to-government) — a government analytics dashboard whose numbers are silently wrong by default fails the phase goal's literal wording.
Output: `buildFilters()` and `getRevenueToGovernment()`'s independent `fromFilter`/`toFilter` block both compute an exclusive next-day boundary for `to` and use `<` instead of `<=`. `from` is unchanged. Regression tests cover all 3 affected query methods.
</objective>
