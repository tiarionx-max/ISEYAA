# Phase 14 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no `components.json` exists anywhere in the repo; this is a deliberate call, not an oversight. Six existing web admin pages (`web/src/app/admin/page.tsx`, `admin/tours/revenue`, `admin/tours/utilization`, `admin/tours/queue`, `admin/guides/queue`, `admin/reviews/queue`) already establish a mature, consistent dark-glassmorphism design language in hand-rolled Tailwind components. Introducing shadcn for one new dashboard would fragment consistency rather than serve it — **build Ministry Dashboard in the same idiom, do not init shadcn this phase.** |
| Preset | not applicable |
| Component library | none — no Radix/base-ui/MUI primitives anywhere in `web/src`; every UI element is a hand-rolled function component styled with Tailwind utility classes + the custom CSS utilities in `web/src/app/globals.css` (`.glass`, `.glass-forest`, `.glass-gold`, `.skeleton`, `.btn-primary`/`.btn-gold`/`.btn-ghost`/`.btn-forest`, `.card-hover`) |
| Icon library | `lucide-react` (already a dependency). Precedent icons in sibling admin pages: `BarChart3`, `TrendingUp`, `Grid3x3`, `CheckCircle`, `XCircle`, `Star`, `Flag`, `MessageCircle`. For this phase use: `Users` (visitor entries), `MapPin` (LGA breakdown), `Compass`/`Tag` (purpose-of-visit), `TrendingUp` (revenue-to-government), `Download` (export actions), `FileText` (PDF format), `Table2` (CSV format) |
| Font | Plus Jakarta Sans via `var(--font-jakarta)` (Tailwind `font-sans`/`font-display`), fallback `system-ui, sans-serif` — set globally in `web/src/app/globals.css:10` and `web/tailwind.config.ts:8-9`, requires no new font loading |

**Note on brand hex drift:** `CLAUDE.md` documents jungle as `#1C2B2B`, but the actual shipped `web/tailwind.config.ts` and `globals.css` define jungle as `#0c1a0f` (with `jungle-2 #111f14` / `jungle-3 #162619` as elevated-surface variants). This spec uses the **real, currently-rendered values** from the codebase — the authoritative source for a codebase-internal phase — not the stale `CLAUDE.md` claim. Forest (`#1A6B3C`) and gold (`#C8962A`) match `CLAUDE.md` exactly.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tight inline padding |
| sm | 8px | Compact element spacing, chip/badge padding |
| md | 16px | Default card padding (`px-4`/`py-4`), filter input padding |
| lg | 24px | Section padding (`px-6`), header margin-bottom (`mb-6`) |
| xl | 32px | Layout gaps, header margin-bottom on page-level sections (`mb-8`) |
| 2xl | 48px | Reserved — not used at this phase's scale, keep available for future dashboard sections |
| 3xl | 64px | Page top offset below navbar (`pt-16`) |

Exceptions: `gap-2.5` (10px) is an established exception already shipped in every sibling admin page's icon+label header row (`flex items-center gap-2.5`) — carry it forward verbatim for the Ministry Dashboard's panel headers, do not "fix" it to 8px or 12px. `py-10` (40px) is the established page-content vertical padding (`max-w-5xl mx-auto px-6 py-10`) — reuse this exact wrapper for the Ministry Dashboard's outer container.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular, unclassed default) | 1.5 |
| Label | 10px | 700 (bold) — `uppercase tracking-widest`, `text-white/30` | 1.2 |
| Heading | 20px | 900 (black) — page `<h1>` | 1.2 |
| Display | 24px | 900 (black) — KPI stat figures in summary cards | 1.1 |

**Established weight exceptions (carried forward from all six sibling admin pages, not new inventions):**
- **600 (semibold)** is reserved for single-value data emphasis inline within a table row (e.g. a name/ID standing out from surrounding regular-weight text) — mirrors `RevenueBreakdownChart`'s vendor-summary row pattern (`text-white font-semibold text-sm`).
- **700 (bold)** doubles as the button/CTA weight (`.btn-gold`, `.btn-forest`, `.btn-ghost` all set `font-weight: 700`) in addition to its Label role above.

This is a 4-weight house style (400/600/700/900), not a fresh 2-weight rule — six already-shipped admin pages use exactly this set. Forcing an artificial 2-weight constraint here would make the new Ministry Dashboard visually inconsistent with its immediate siblings; consistency with `admin/tours/revenue` and `admin/tours/utilization` (the two closest analogues, per RESEARCH.md's own reuse recommendation) takes priority.

Secondary body/meta text (subtitles, filter date ranges, empty-state captions) renders at 12px/400/1.4 (`text-xs text-white/35` or `text-white/30`) — an established sub-size of Body, not a fifth declared role.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Export PDF"** — gold (`.btn-gold`), the presentation-ready format a Ministry stakeholder would actually walk into a meeting with; paired with a secondary, lower-emphasis **"Export CSV"** (`.btn-ghost`) alongside it for raw-data use |
| Empty state heading | **"No entries for this period"** |
| Empty state body | **"Try a wider date range or clear the LGA filter to see more results."** — always paired with the heading, never shown alone (mirrors `admin/tours/utilization.tsx`'s existing empty-state pattern: icon + one-line message, no heading/body split today — this phase upgrades to a heading+body pair since Ministry stakeholders are less familiar with the platform than internal admins and need the explicit next step) |
| Error state | **"Couldn't load dashboard data."** / **"Check your connection and try again."** — problem first, concrete next step second; no raw error codes/stack traces ever surfaced to a `MINISTRY_VIEWER` |
| Destructive confirmation | **Not applicable this phase.** Ministry Dashboard is read-only end-to-end (MIN-01) — no delete/reject/approve action exists anywhere in this surface. If a future phase adds a mutation to a Ministry-adjacent surface, it must live in a *different* controller/page per MIN-01's own constraint, and would need its own copy contract at that time. |

**Role-gate copy (mirrors existing `ALLOWED_ROLES` + `redirect()` pattern verbatim, no new UX to invent):**
- `ALLOWED_ROLES = ['MINISTRY_VIEWER', 'STATE_ADMIN', 'SUPER_ADMIN']`
- `status === 'unauthenticated'` → `redirect('/login')`
- Authenticated but role not in `ALLOWED_ROLES` → `redirect('/')` (Ministry viewers have no legitimate reason to land on `/admin`, unlike the existing tours pages which redirect disallowed roles to `/admin`)

**Export button microcopy while streaming:** "Export PDF" → "Preparing…" (disabled state) → returns to "Export PDF" on completion/failure; same pattern for CSV. No toast needed for success (the browser's native download indicator is sufficient); on failure, use the existing `sonner` `toast.error('Export failed — try again')` pattern already used elsewhere in `web/src` (e.g. `admin/reviews/queue.tsx` imports `toast` from `sonner`).
