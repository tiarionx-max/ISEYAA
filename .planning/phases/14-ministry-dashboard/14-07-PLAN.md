<objective>
Complete MIN-05 (CSV export) and MIN-06 (branded PDF export) for all 3 Ministry reports. `MinistryPdfService` reuses `ItineraryPdfService`'s branded shell (Forest Green `#1A6B3C` headings, Jungle `#1C2B2B` body, Gold `#C8962A` divider, buffer-collection `Promise` wrapper, footer text) but needs a NEW tabular row-rendering method — the existing itinerary body-rendering loop is hardcoded to a single-booking narrative list, not a multi-row table (D-13). It also needs to support rendering **multiple sequential tabular sections in one PDF document**, because revenue's export must carry all three breakdown dimensions (byModule/byMonth/byModuleLga), not just one. Exports are direct streamed HTTP responses (`@Res()` + `Content-Disposition: attachment`), not the S3-upload-then-URL pattern `ItineraryPdfService.generateAndUpload()` uses — Ministry exports are on-demand ad-hoc downloads of live filtered data, not persisted-per-booking artifacts.

Purpose: This is the last backend plan before the web dashboard (Plan 14-08), which calls these 6 export routes directly.
Output: `MinistryPdfService` (new, CommonModule-registered, section-aware), 6 new `GET /ministry/*/export?format=csv|pdf` routes, all respecting the active `from`/`to`/`lgaId` filter (D-14). Revenue's export (both formats) carries all three of `getRevenueToGovernment()`'s dimensions.
</objective>
