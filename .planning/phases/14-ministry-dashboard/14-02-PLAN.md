<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Feature-module write calls → `VisitorLogService.record()` | In-process, first-party calls only (D-08) — no untrusted external input reaches this service directly; input shaping/validation happens at the DTO layer in the calling module |
| Report row data → `CsvExportService.toCsv()` | Row values originate from this platform's own DB (LGA names, module names, counts, currency amounts) — not raw user-free-text at export time, per RESEARCH.md's CSV-injection risk assessment |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03 | Tampering | `CsvExportService.toCsv()` | mitigate | Uses `fast-csv`'s RFC4180-compliant escaping instead of a hand-rolled `.join(',')` — embedded commas/quotes/newlines in LGA names or purpose labels cannot silently corrupt column alignment |
| T-14-04 | Tampering | CSV formula injection (`=`, `+`, `-`, `@` prefixed values opened in Excel) | accept | All Ministry CSV columns are system-generated (LGA names, module names, counts, currency totals) — no user-free-text field is exported by this phase, so formula-injection risk is low; revisit if a future phase adds a free-text column to an export |
</threat_model>
