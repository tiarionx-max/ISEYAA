<objective>
Extract Waitlist — position 2 in the D-05 risk-ascending order — into its own independently-deployable gRPC process, identical shape to News (Plan 21-02) but with one genuinely new piece of client-side logic: the proto's `GetWaitlistStats` RPC takes a single `source` and returns a single `total_count`, but the current REST endpoint returns ALL sources grouped in one call. Additionally, `JoinWaitlistResponse` only carries `{id, success}` while the current REST response is `{message, position, id}` — this second shape gap is not documented in RESEARCH.md/21-PATTERNS.md and must be resolved the same way: reconstruct the exact response shape in the monolith facade using direct Prisma access (the established "no data-ownership boundary" pattern), never by silently dropping fields.

Purpose: Prove the shape-reconciliation pattern (facade re-queries Prisma after a thin gRPC call to reassemble a REST-facing response) on a still-low-risk, pure-CRUD domain before Reviews needs the same technique with higher stakes.
Output: `backend/apps/waitlist-service/` + `backend/src/modules/waitlist-client/` + updated `waitlist.module.ts`/`waitlist.controller.ts`/`app.module.ts` wiring.
</objective>
