<objective>
Extract Delivery's `VerifyDeliveryOtp` RPC — the highest-risk, final service in the D-05 rollout order, since it touches Redis+Postgres state (`delivery:otp:*` keys, `deliveryOrder.otpVerifiedAt`) that the still-in-process `DeliveryService` (RequestDelivery/AcceptDelivery/CompleteDelivery/DeliveryGateway) continues to read and write live. Per D-01, `delivery-otp-service` reuses the full `DeliveryModule` as-is (wholesale import, matching `notifications-service`'s pattern) rather than extracting a lean OTP-only module.

This plan resolves Pitfall 5 concretely rather than leaving it as an open assumption: by reading `node_modules/@nestjs/microservices/exceptions/base-rpc-exception-filter.js` directly, this phase confirms that NestJS's DEFAULT `@GrpcMethod` exception handling does NOT preserve a thrown `BadRequestException`'s message across the gRPC boundary — non-`RpcException` errors are replaced with the generic string `MESSAGES.UNKNOWN_EXCEPTION_MESSAGE` ("Internal server error"). Without an explicit fix, a driver who enters the wrong OTP would see "service unavailable" instead of "incorrect OTP, N attempts remaining" — this plan's gRPC controller task builds the fix (explicit `RpcException` wrap with a structured `{code, message}` payload) as its own first-class task, not an afterthought.

Purpose: Land the server side of the Delivery OTP extraction, including the one design element (business-exception-vs-transport-exception gRPC mapping) with no precedent anywhere else in this codebase.
Output: `backend/apps/delivery-otp-service/` (new independently-buildable NestJS app, wholesale-importing DeliveryModule).
</objective>

`DeliveryService.verifyOtp(orderId, dto)` (backend/src/modules/delivery/delivery.service.ts:489-521) — UNCHANGED by this plan. Throws `NotFoundException('Delivery order not found')` if the order doesn't exist; `BadRequestException('Too many OTP attempts — order is locked. Contact support.')` after 5 failed attempts; `BadRequestException('OTP expired. Request a new delivery to get a fresh code.')` if the Redis key is gone; `BadRequestException('Incorrect OTP. Ask the recipient to check their SMS. N attempt(s) remaining.')` on a wrong OTP. Returns `{ verified: true }` on success.

`@nestjs/microservices` exports `RpcException` — confirmed available in this repo's installed version via direct `require()` check this session. `BaseRpcExceptionFilter.catch()` (the filter NestJS applies by default to every `@GrpcMethod`, unless a custom filter is registered) does: if the thrown exception is NOT an `RpcException`, return `{status:'error', message: MESSAGES.UNKNOWN_EXCEPTION_MESSAGE}` — the ORIGINAL exception message is discarded. If it IS an `RpcException` whose `getError()` returns an object, that object (plus the exception's own `.message`) is returned as-is. `@grpc/grpc-js`'s `status` enum (already imported elsewhere in this codebase as `import { status as GrpcStatus } from '@grpc/grpc-js'` in `resilience.service.ts`) provides `INVALID_ARGUMENT = 3` and `NOT_FOUND = 5`.
