# Phase 15 — Multi-Channel OTP — UI Design Contract

> Visual and interaction contract for the OTP channel-selection UI additions: registration channel
> picker, SMS-fallback notice, and post-registration settings control.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Inherits and extends `mobile/lib/tokens.ts` and `.planning/mobile-redesign-UI-SPEC.md` —
> does not redefine the base token system, only declares this phase's new surfaces.

**Scope confirmation (from RESEARCH.md Pitfall 2):** This phase is **mobile-only**. The web app's
`POST /auth/register` (email+password) has zero OTP interaction today and is unaffected. All UI
in this contract lives under `mobile/app/`.

## Spacing Scale

Reusing the project's existing scale — no new values introduced by this phase.

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| `SPACE_1` | 4px | Icon-to-label gap inside channel option cards |
| `SPACE_2` | 8px | Gap between the 3 channel-picker cards |
| `SPACE_3` | 12px | Fallback banner internal padding (vertical), row separator inset |
| `SPACE_4` | 16px | Settings screen horizontal padding, option row padding, banner horizontal padding |
| `SPACE_5` | 20px | Fallback banner bottom margin (above OTP boxes) |
| `SPACE_6` | 24px | Settings screen subheading bottom margin |

**Exceptions:**
- Touch targets: minimum 44×44px on every pressable — back button, each channel option card/row, and the profile Menu Row all meet this (channel picker cards are 76px tall; settings rows are 16+16 vertical padding + content ≥ 44px effective height)
- No new exception beyond the project-wide 44px floor already documented in `mobile-redesign-UI-SPEC.md`

## Typography

**New-element type scale for this phase — exactly 4 sizes, exactly 2 weights** (matches the
codebase's actual convention in `phone.tsx`/`otp.tsx`/`profile.tsx`: weights are 400 and 700, never 600):

| Role | Size | Weight | Line Height | Color Default | Usage |
|------|------|--------|-------------|----------------|-------|
| Display | 42px | 400 | 1.19 (50/42) | `CREAM` | Pre-existing screen titles on `phone.tsx`/`otp.tsx` — unchanged, inherited, not newly introduced |
| Heading | 22px | 700 | 1.27 | `INK` | Settings screen title ("Verification Channel") |
| Body | 14px | 400 / 700 | 1.5 | `INK` / `INK_SECONDARY` | Channel option labels, row titles (700), descriptions, banner primary text (700), fallback secondary text (400) |
| Caption | 12px | 400 | 1.4 | `INK_FAINT` / `INK_DIM` | Channel option card labels, settings row sub-text, error text under settings group |

**Footnote:** The 10px monospace "kicker" label (`SIGN IN` / `VERIFY`) on `phone.tsx`/`otp.tsx` is
pre-existing screen furniture, unchanged by this phase, and intentionally excluded from the
4-size scale above (same exception precedent as the Countdown Ring override in
`mobile-redesign-UI-SPEC.md`).

**Rules:**
- Weight 700 = bold/emphasis role for this codebase (there is no 600 weight in any touched file — do not introduce one)
- Body line height 1.5 is mandatory on all description/banner text (matches existing project rule)
- No font size smaller than 12px

## Color

All values from `mobile/lib/tokens.ts` (verbatim, read directly this session) — no new hex values introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `SURFACE_MID` `#0D1F1F` | New settings screen (`mobile/app/otp-channel-settings.tsx`) background — matches the existing `kyc.tsx` background precedent. `phone.tsx`/`otp.tsx` keep their existing `SURFACE_DEEP` + gradient background, unchanged. |
| Secondary (30%) | `SURFACE_RAISED` `#162B2B` | Channel option cards (default state), settings-screen option-row group container, unselected row background |
| Accent (10%) | `GOLD` `#D4A843` | Reserved for: the selected channel option card's border + icon + label color; the selected settings-row's icon-box background (`GOLD_DIM`) + icon + trailing checkmark; the existing "Send code →" CTA button (unchanged, already gold). **Never** used for: unselected option borders, banner text/icon, sub-labels, or the profile Menu Row icon. |
| Info/Success accent | `SUCCESS_DIM` `rgba(46,204,113,0.14)` / `SUCCESS_TEXT` `#7BE7A2` | Fallback-notice banner background/border tint and icon — deliberately **not** gold, to keep gold reserved for interactive/selection state only (an informational "this worked, just via a different channel" banner is a distinct semantic role from the accent color) |
| Destructive | `ERROR` `#E05252` / `ERROR_TEXT` `#F08F8F` | Settings-save failure inline error text only. No destructive (delete/cancel) actions exist in this phase's UI — `DESTRUCTIVE` token is not used here. |

Accent reserved for: selected channel-picker card (border/icon/label), selected settings-row (icon box bg/icon/checkmark), and the pre-existing "Send code →" button. Never for banner content, unselected states, or body/caption text.

## Component Specs (new, this phase)

### 1. Channel Picker (registration — `mobile/app/auth/phone.tsx`)

Inserted between the phone number input and the "Send code →" CTA button.

```
Label above row: "How should we reach you?" — Caption (12px, 700, INK_SECONDARY, letterSpacing 0.3), marginBottom 8

Row: 3 cards, flexDirection: row, gap: SPACE_2 (8px), marginBottom: SPACE_4 (16px)

Each card (flex: 1):
  Height: 76px
  Border radius: 14px (RADIUS_MD)
  Border width: 1.5px

  Default (unselected):
    Background: SURFACE_MID
    Border color: BORDER (rgba(255,255,255,0.06))
    Icon: 22px, color INK_MID
    Label: Caption 12px, weight 700, color INK_MID

  Selected:
    Background: GOLD_DIM
    Border color: GOLD
    Icon: 22px, color GOLD
    Label: Caption 12px, weight 700, color GOLD

  Icons (lucide-react-native): SMS → MessageSquare · WhatsApp → MessageCircle · Email → Mail
  Labels: "SMS" · "WhatsApp" · "Email"

  Default selection on mount: SMS (satisfies OTP-01's "defaults to SMS if unselected")
  Press: Haptics.selectionAsync() — no scale animation (instant state change, matches Chip convention)
  Accessibility: accessibilityRole="radio", accessibilityState={{ selected }}, accessibilityLabel="{channel} verification channel"
```

The chosen channel is submitted as `channel` on `POST /auth/otp/send` alongside `phone` — the
existing "Send code →" CTA is unchanged in copy/position.

### 2. Fallback Notice Banner (verification — `mobile/app/auth/otp.tsx`)

Shown only when the API response indicates the send fell back to SMS (`fallbackUsed: true`).
Positioned below the "Sent to {maskedPhone}" subtitle, above the OTP digit boxes.

```
Container:
  flexDirection: row, alignItems: flex-start, gap: SPACE_2 (8px)
  Background: SUCCESS_DIM
  Border: 1px rgba(46,204,113,0.30)
  Border radius: 12px
  Padding: SPACE_3 (12px) SPACE_4 (16px)
  Margin bottom: SPACE_5 (20px)

Icon: Info (lucide-react-native), 16px, color SUCCESS_TEXT, marginTop 1 (optical alignment)

Text block (flex: 1):
  Primary line: "We sent your code via SMS instead" — Body 14px, weight 700, color INK
  Secondary line: "Your original channel didn't respond in time." — Caption 12px, weight 400, color INK_DIM, marginTop 2

Accessibility: accessibilityLiveRegion="polite", accessibilityRole="text" — screen readers must
announce this banner when it appears without requiring focus
```

Exact copy is locked per CONTEXT.md D-10's literal example — do not vary wording between
implementations.

### 3. Settings Screen — Verification Channel (`mobile/app/otp-channel-settings.tsx`, new file, card presentation)

**Route note:** this project has no nested `settings/` route group — every standalone screen
(`kyc.tsx`, `host.tsx`, `topup.tsx`, `notifications.tsx`) is a flat file registered directly under
`mobile/app/`. This screen follows that same convention: `mobile/app/otp-channel-settings.tsx`,
registered as `<Stack.Screen name="otp-channel-settings" ... />` in `mobile/app/_layout.tsx`.

```
SafeAreaView edges=['top'], background SURFACE_MID

Header row (56px):
  Back button: ChevronLeft 22px INK, 44×44 touch target, top-left
  Title: "Verification Channel" — Heading 22px, weight 700, INK — centered or left-aligned per existing kyc.tsx header convention

Subheading: "Choose how you'd like to receive your verification codes." — Body 14px, weight 400,
  INK_SECONDARY, lineHeight 21, marginBottom SPACE_6 (24px)

Option group container:
  Background: SURFACE_RAISED
  Border radius: 16px
  Border: 1px BORDER_SUBTLE
  Overflow: hidden
  (identical container spec to the existing Menu Row group in profile.tsx)

Each option row (SMS / WhatsApp / Email, in that order):
  flexDirection: row, alignItems: center
  paddingHorizontal: SPACE_4 (16px), paddingVertical: SPACE_4 (16px)
  Separator: 1px BORDER_SUBTLE (all rows except the last)

  Icon box: 32×32, borderRadius 9px
    Selected: background GOLD_DIM, icon 16px GOLD
    Unselected: background SURFACE_HIGH, icon 16px INK_SECONDARY
    Icons: MessageSquare (SMS) · MessageCircle (WhatsApp) · Mail (Email) — same icons as the registration picker

  Label block (flex: 1, marginLeft 12):
    Title: "SMS" / "WhatsApp" / "Email" — Body 14px, weight 700, INK
    Sub: "Delivered via text message" / "Delivered via WhatsApp" / "Delivered via email" —
      Caption 12px, weight 400, INK_FAINT

  Trailing:
    Selected: CheckCircle2 icon, 20px, GOLD
    Unselected: 20px empty spacer (maintains row alignment)
    In-flight (saving): ActivityIndicator, size small, color GOLD (replaces the trailing icon only
      for the row being changed to)

  Press behavior: instant-apply, no separate "Save" button.
    1. Optimistically highlight the tapped row as selected
    2. PATCH /users/me/otp-channel with the new value
    3. On success: leave selection as-is, Haptics.selectionAsync()
    4. On failure: revert to the previous selection + show inline error text below the group

  Accessibility: accessibilityRole="radio" on each row, accessibilityState={{ selected }},
    group wrapped with accessibilityRole="radiogroup" and accessibilityLabel="Verification channel"

Inline error text (shown only after a failed save, below the option group):
  "Could not update your verification channel. Please try again." — Caption 12px, weight 400,
  ERROR_TEXT, marginTop SPACE_2 (8px)
```

### 4. Profile ("You" tab) — new Menu Row entry (`mobile/app/(tabs)/profile.tsx`)

Add one new entry to the existing `menuRows` array (uses the pre-existing `MenuRow` component —
no new component needed here):

```
icon: MessageSquare (lucide-react-native) — parity with the SMS/OTP concept
label: "Verification Channel"
sub: dynamic — current value of user.otpChannel, title-cased: "SMS" | "WhatsApp" | "Email"
onPress: () => router.push('/otp-channel-settings')
```

Placement: insert immediately before the existing "Security & ID" row (both are
identity/security-adjacent settings); "Security & ID" keeps `isLast: true`.

## Accessibility Requirements

- All interactive elements: minimum 44×44 touch target (channel picker cards are 76px tall;
  settings rows and the back button meet this via existing padding conventions)
- Channel picker cards: `accessibilityRole="radio"`, `accessibilityState={{ selected }}`,
  `accessibilityLabel="{channel} verification channel"`
- Settings option group: `accessibilityRole="radiogroup"` wrapper, each row `accessibilityRole="radio"`
- Fallback banner: `accessibilityLiveRegion="polite"` so screen readers announce it without
  requiring manual focus
- Settings save loading state: `accessibilityState={{ busy: true }}` on the row being saved
- Icon-only back button: `accessibilityLabel="Go back"`
