<objective>
Add `SendgridService.sendOtpEmail()` as a new, deliberately non-swallowing method — the one new SendGrid capability this phase needs (email has never been an OTP channel before). This plan is intentionally independent of Plan 15-01's schema/DTO work: `sendOtpEmail()`'s signature (`to`, `firstName`, `otp` strings) has no dependency on `OtpChannel` or Prisma, so it can run in parallel Wave 1.

Purpose: RESEARCH.md's Pitfall 1 identifies that this file's existing `sendEmail()` swallows every failure internally and always resolves — if `sendOtpEmail()` naively reused it, `resilience.execute('sendgrid', ...)` in Plan 15-03 would never observe a rejection and the SMS fallback (OTP-02) would silently never fire for email. This plan proves the fix in isolation before Plan 15-03 wires it in.
Output: `SendgridService.sendOtpEmail()` and a new spec file proving its rejection-propagation behavior, with a non-regression check that `sendEmail()`'s existing fire-and-forget behavior is untouched.
</objective>
