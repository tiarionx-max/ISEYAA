## STRIDE Threat Register

|-----------|----------|-----------|-------------|-------------------|
| T-17-04-01 | Denial of Service | `POST /notifications/send`, `POST /notifications/register-token` | mitigate | On facade failure these REST paths now return HTTP 503 (via `ServiceUnavailableException`) instead of the old always-succeeds-or-inline-failure-reason path — the client sees a clear, retryable error rather than a silently wrong answer (D-06) |

| T-17-04-03 | Repudiation (audit gap) | `TourNotificationsService`'s cron/event handlers now degrade silently on a `notifications-service` outage | accept | Matches the pre-existing catch-and-log-no-rethrow contract (D-07) — notifications are best-effort by design; a missed push reminder is not a financial or compliance-critical failure |
</threat_model>
