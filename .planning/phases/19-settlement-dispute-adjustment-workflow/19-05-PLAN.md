<objective>
Close the 3 CRITICAL gaps confirmed independently by both `19-VERIFICATION.md` (gsd-verifier, score 3/5) and `19-REVIEW.md` (gsd-code-reviewer, CR-01/CR-02/CR-03) that are blocking Phase 19's goal. This is a targeted fix, not a redesign: the dispute state machine (`raise/moveToReview/resolve/dismiss`, 5-status including `BLOCKED`) and `SettlementService.adjust()` primitive are both sound and stay exactly as they are.

Three fixes, all localized to `SettlementDisputesService`:
1. **CR-01 (BLOCKER, falsifies SETTLE-10c):** `computeAdjustmentLines()` never emits a platform-wallet adjustment line, so every dispute resolution that changes the earner/ministry split creates or destroys money instead of reallocating it between earner, ministry, and platform. Fix: compute a self-balancing `correctPlatformTotal` (mirrors `settle()`'s own drift-absorption design) and push a platform delta line.
2. **CR-02 (BLOCKER, undermines SETTLE-10a/10e):** `raise()`'s "one active dispute per settlement" guard is a non-atomic `findFirst()` + `create()` with no DB backstop. Fix: a new partial unique index (mirroring `SettlementSplitTier`'s proven pattern) plus a P2002 catch in `raise()` translating the DB-level rejection into the same `ConflictException` the pre-check already throws.
3. **CR-03 (BLOCKER, correctness guardrail):** `raise()` never validates `dto.module` against the settlement transaction's actually-recorded module, so a fat-fingered module selection silently drives `resolveSplit()` to the wrong tier. Fix: select `metadata` on the existence check and reject a mismatch with `BadRequestException`.

Purpose: make Phase 19's "corrected through an auditable, non-destructive adjustment" goal actually true, and close the TOCTOU/module-mismatch integrity gaps compounding it — without touching the state machine or `adjust()` primitive, both of which verification/review confirmed are already correct.

Output: money-conserving `computeAdjustmentLines()`, DB-enforced one-active-dispute-per-settlement invariant, module cross-check in `raise()`, and updated unit + e2e tests proving all three (plus regression-proof that the 3 already-passing truths are untouched).
</objective>
