## Scope Note (read first)

Per `22-CONTEXT.md` D-09, this phase has **exactly one new UI surface**: an `LgaMonthHeatmap` panel added to the existing `web/src/app/admin/ministry/page.tsx` dashboard. The subscription CRUD (MIN-08b/D-10) is **backend-only** (`SUPER_ADMIN`-gated REST routes, Swagger-visible, no web admin panel this phase) — it has no design contract surface. Everything below governs the heatmap panel only, and is 100% derived from the *existing, already-shipped* Ministry Dashboard design system (Phase 14) — this phase introduces **zero new design tokens**, only a new component built from tokens/classes that already exist in the codebase.

## Spacing Scale

Declared values (must be multiples of 4) — **inherited from the existing Ministry Dashboard page, not new to this phase**:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Grid cell gaps (`gap-1`), icon-to-text gaps |
| sm | 8px | Compact element spacing (`gap-2`) |
| md | 16px | Panel body padding (`px-4 py-5`), filter gaps (`gap-4`) |
| lg | 24px | Section bottom margin between panels (`mb-6`) |
| xl | 32px | Header-to-filters margin (`mb-8`) |
| 2xl | 48px | not used by this panel |
| 3xl | 64px | not used by this panel |

Additional established value in use: **20px** (`px-5 py-4` — panel header padding). Not in the canonical 8-pt list but already the codebase's fixed convention for every panel header (Visitor Entries, Purpose of Visit, Revenue) — the new heatmap panel header MUST reuse this exact `px-5 py-4` value for visual consistency with its 3 sibling panels, not the canonical `lg`/24px token.

Exceptions: none — heatmap grid cell size (28px = `h-7 w-7`) and gap (4px = `gap-1`) are both clean multiples of 4.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0c1a0f` (`bg-jungle`) | Page background (unchanged) |
| Secondary (30%) | `rgba(255,255,255,0.035)` + `border rgba(255,255,255,0.07)` (`.glass`) | Heatmap panel card wrapper — identical `.glass rounded-2xl border border-white/6 overflow-hidden mb-6` shell used by the other 3 panels |
| Accent (10%) | `#C8962A` (gold) | **NOT used anywhere in the heatmap component.** See below. |
| Destructive | not applicable | No destructive UI action exists in this phase's scope (subscription delete is a backend-only Swagger route per D-09 — no frontend confirmation UI to spec) |

**Accent reserved for:** Revenue-to-Government panel icon badge, its `TrendingUp` icon, and the shared `.btn-gold` PDF-export buttons across all 3 *existing* panels — i.e. gold is reserved exclusively for **financial/revenue-adjacent elements**. This is an established, twice-documented codebase convention (`VisitorEntriesChart.tsx:83` and `PurposeBreakdownChart.tsx:59` doc comments both state "non-financial data — forest family only ... no gold"). Visitor-count/heatmap data is non-financial by the exact same rule, so:

- Heatmap panel icon badge: `bg-forest/20 border border-forest/30`, icon `text-forest-light` (matches Visitor Entries' `Users` icon badge exactly, not Revenue's gold badge)
- Heatmap cell intensity scale: forest family only, 5 fixed opacity tiers (no gradient function, no gold):

| Bucket | Condition (ratio = cell count / max count in current filtered result set) | Style |
|--------|------|-------|
| None | count === 0 | `bg-white/5` (near-invisible, matches empty-cell convention used elsewhere) |
| Low | 0 < ratio ≤ 0.25 | `rgba(26,107,60,0.25)` |
| Medium | 0.25 < ratio ≤ 0.5 | `rgba(26,107,60,0.45)` |
| High | 0.5 < ratio ≤ 0.75 | `rgba(26,107,60,0.65)` |
| Peak | ratio > 0.75 | `rgba(26,107,60,0.9)` |

Max is scoped to the **current filtered result set** (not a fixed global max) — matches how the other 3 panels already scope their visuals to the active `from`/`to`/`lgaId` filter (RESEARCH.md Pattern 5).

## Component Contract — `LgaMonthHeatmap`

Executor-facing implementation contract (visual, not code):

- **File:** `web/src/components/admin/ministry/LgaMonthHeatmap.tsx` (new), mounted as a 4th panel in `web/src/app/admin/ministry/page.tsx`, positioned after the existing Revenue panel, before the closing `</div>`.
- **Panel shell:** identical wrapper to the other 3 panels — `className="glass rounded-2xl border border-white/6 overflow-hidden mb-6"`, header `flex items-center justify-between gap-2 px-5 py-4 border-b border-white/6` containing the icon badge + `<h2 className="font-bold text-white text-sm">LGA × Month Visitor Density</h2>` — **no button group in the header** (unlike the other 3 panels, which have PDF/CSV export buttons — this panel has none, per D-08).
- **Body wrapper:** `px-4 py-5` (matches existing panels), containing loading/error/empty states using the identical `.skeleton` / `ErrorPanelState` / `EmptyPanelState` conventions, then the grid itself.
- **Data source:** consumes the exact same `visitorEntries` query already fetched on the page (`GET /ministry/visitor-entries?from=&to=&lgaId=`) — no new network request (D-05: zero new backend query work). Client-side aggregation groups by `(lgaName, month)` summing `count` across `userRole` (RESEARCH.md Pattern 5 / Pitfall 5 — must NOT group by `lgaName` alone, which would collapse the month axis).
- **Grid axes:** rows = all 20 `OGUN_LGA_NAMES` (imported from `@iseyaa/shared`), always shown even at zero count (D-07); columns = distinct months present in the current filtered result set, sorted chronologically.
- **Grid layout:** CSS grid or table, cell size `h-7 w-7` (28px, `rounded-sm`), `gap-1` (4px) between cells. Row labels (LGA name) sticky-left, `text-xs text-white/60 truncate`, fixed width ~120px. Column labels (month) sticky-top, `text-[10px] uppercase tracking-widest text-white/35`.
- **Scroll behavior:** `overflow-x-auto` for many months, `max-h-[420px] overflow-y-auto` for the 20-row list (matches the existing 280px chart-height convention, scaled up for a taller list-of-20 use case).
- **Legend:** horizontal row beneath the grid, 5 swatches (`h-3 w-3 rounded-sm`) + labels, `text-[10px] uppercase tracking-widest text-white/30` (matches existing filter-label styling exactly).
- **Reused filters:** no new filter UI — the heatmap reacts to the page's existing `from`/`to`/`lgaId` inputs (D-07), same as the other 3 panels.
