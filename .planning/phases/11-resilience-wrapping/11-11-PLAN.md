<objective>
Close WR-03 and the remaining 3-of-5 file slice of WR-02 from `11-REVIEW.md` (fresh code review of the gap-closure batch that produced `11-VERIFICATION.md`'s primary finding, closed separately for `ai.service.ts` in Plan 11-09 and `notifications.service.ts` in Plan 11-10).

**WR-03:** `isTransientError()` (`resilience.service.ts:194-216`) recognizes the native fetch/undici abort code `'ABORT_ERR'` but not axios 1.x's own cancellation code `'ERR_CANCELED'` (axios's `CanceledError.code === 'ERR_CANCELED'`, `CanceledError.name === 'CanceledError'` — neither currently matched by the allowlist or the `AbortError` name check). When cockatiel's aggressive timeout fires and aborts the shared `AbortSignal` passed into axios, axios rejects with this `CanceledError` shape. Today this is usually masked because cockatiel's own `TaskCancelledError` (already handled, `isTaskCancelledError: true`) wins the race first — but this is a timing coincidence, not a guarantee (e.g. it would break under a future move to `TimeoutStrategy.Cooperative`, which does not race and instead waits for `fn` to observe and honor the abort itself). Fix: add `'ERR_CANCELED'` to the recognized allowlist.

**WR-02 (remaining 3-file sweep):** Only `paystack.service.spec.ts` asserts AbortSignal reference-identity (the *exact same* signal instance cockatiel provides reaches the underlying vendor call). `s3.service.spec.ts`, `auth.service.spec.ts`, and `delivery.service.spec.ts` do not (the other 2 of the original 5 — `ai.service.spec.ts` and `notifications.service.spec.ts` — are closed in Plans 11-09/11-10). Add the assertion to each, mirroring paystack's pattern.

Purpose: Harden error classification against a plausible future timeout-strategy change, and close a test-coverage gap that would let a future refactor silently drop AbortSignal forwarding in 3 vendor call sites without any test catching it.
Output: `isTransientError` recognizes axios's cancellation code; one new regression test proving it; three new reference-identity tests (one per remaining spec file).
</objective>
