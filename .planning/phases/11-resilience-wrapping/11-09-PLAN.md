<objective>
Close the ONE blocking gap in `11-VERIFICATION.md` (re-verification, 2026-07-16): `ai.service.ts`'s `streamChatWithTools` (~L279-290) and `streamItinerary` (~L494-503) wrap `this.anthropic.messages.stream(...)` in `resilience.execute('anthropic', ...)`, but `.messages.stream()` is synchronous — it returns a `MessageStream` object immediately while the real HTTP request runs fire-and-forget via the SDK's internal `_run()`. The wrapped callback therefore resolves in microtask time, so cockatiel's 8000ms per-attempt timeout and the `'anthropic'` circuit breaker (`failureThreshold: 3`) never get a genuine window to observe a hung or failing connection on these two paths. `getLgaIntelligence` (uses `.messages.create()`, a real Promise) is unaffected and must not be touched.

Per `11-REVIEW.md` CR-01 (the authoritative root-cause trace against `node_modules/@anthropic-ai/sdk/lib/MessageStream.js`), the fix is to `await stream.withResponse()` inside the wrapped callback before returning the stream — `withResponse()` awaits the SDK's internal `_connectedPromise`, which only resolves once the underlying HTTP response begins. This gives cockatiel's per-attempt timeout a real window to enforce and lets the circuit breaker see genuine connection-level failures. The misleading comment above both call sites (which asserts a resilience contract the code never delivered, and is precisely why this defect survived 3 prior plans per 11-REVIEW.md's own anti-pattern finding) must be corrected in the same pass.

Purpose: Make RESIL-01 ("every vendor call site wrapped in a circuit-breaker + retry + timeout + fallback policy that functions correctly under real vendor latency") actually true for the two highest-traffic, most latency-sensitive AI endpoints (chat, itinerary generation) — not just syntactically present.
Output: Both call sites genuinely bounded by cockatiel's timeout/breaker; a fake-timer regression test (using the real `ResilienceService`, mirroring `retry-timeout-composition.spec.ts`) that would fail under the old code and passes under the fix; an AbortSignal reference-identity test closing WR-02 for this file.
</objective>
