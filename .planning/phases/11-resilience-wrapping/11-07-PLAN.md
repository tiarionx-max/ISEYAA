<objective>
Close CR-02 (missing AbortSignal propagation) from `11-VERIFICATION.md`/`11-REVIEW.md` for the 3 centralized-service vendor call sites: `paystack.service.ts` (initiatePayment, resolveBvn, refundCharge), `s3.service.ts` (upload), and `notifications.service.ts` (sendPush). Every one of these currently discards cockatiel's `context.signal` — meaning an "aggressive" timeout stops the CALLER from waiting but never cancels the real in-flight request. For `refundCharge` specifically this is the exact double-refund race `paystackRefund.retryCount: 0` (threat T-11-05) was designed to prevent: a client-side "timed out" refund can still succeed server-side after the caller has already surfaced failure. This plan threads `signal` through all 5 call sites, updates each affected spec file's mock so the new `{ signal }` destructuring doesn't crash existing tests, and adds the one required regression test proving signal forwarding actually happens (using paystack as the canonical example per the gap closure scope).

Purpose: These 3 files are 3 of the 6 files `11-VERIFICATION.md` names as CR-02 defect sites; this plan closes exactly that subset without touching `resilience.service.ts` (Plan 11-06) or the AI/Termii call sites (Plan 11-08), keeping file ownership disjoint for parallel execution.
Output: `signal` forwarded at 5 call sites across 3 production files; all 3 corresponding spec files' mocks fixed to pass a context object instead of calling `fn()` bare; one new regression test proving reference-identity forwarding.
</objective>
