<objective>
Wrap `NotificationsService.sendPush()` (FCM) and `AiService`'s three Anthropic call sites (`streamChatWithTools`, `streamItinerary`, `getLgaIntelligence`) in the `ResilienceService` policy from Plan 01 — preserving FCM's existing never-throw swallow-and-report contract (D-02) and applying the connection-only retry boundary to Anthropic's two SSE methods so a mid-stream failure is never retried.

Purpose: FCM already has the D-02 fallback baked in; this plan makes that fallback observable via cockatiel without changing its shape. Anthropic is the one vendor whose SDK has its own internal retry logic — this plan neutralizes that (`maxRetries: 0`) so cockatiel becomes the single source of retry truth, and fixes `getLgaIntelligence`'s complete lack of error handling as a required byproduct.
Output: `notifications.service.ts` and `ai.service.ts` route their vendor calls through `resilience.execute()`; new `notifications.service.spec.ts` test file; extended `ai.service.spec.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend → Firebase FCM (`fcm.googleapis.com`) | Outbound HTTPS carrying push notification payloads + OAuth bearer token; must never throw uncaught (D-02) |
| Backend → Anthropic API (`api.anthropic.com`) | Outbound HTTPS/SSE carrying user chat content + system prompts; connection failures must fail loud (D-01), mid-stream failures must never silently retry |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Information Disclosure | `ai.service.ts` `getLgaIntelligence` catch block | mitigate | New catch block throws a static `ServiceUnavailableException` string, never `err.message`/raw Anthropic error body — verified by Task 2's dedicated test case |
| T-11-02 | Denial of Service (retry amplification / compounding retries) | `ai.service.ts` Anthropic client construction | mitigate | `maxRetries: 0` on the `Anthropic` client removes the SDK's own internal retry layer so cockatiel's retry (owned in Plan 01, `resilience.anthropic.retry_count` default `0`) is the single source of retry truth — prevents the `(1+SDK retries)×(1+cockatiel retries)` compounding described in RESEARCH.md Pitfall 3 |
| T-11-03 | Information Disclosure (PII in push payloads/logs) | `notifications.service.ts` `sendPush` catch block | mitigate | Existing catch block already logs only `err?.response?.data ?? err.message` via `Logger.error`, never returns it to the caller — the `{sent:false, reason:'send_failed'}` shape carries no vendor error detail, unchanged by this plan |

See Plan 01's `<threat_model>` for the shared retry-amplification (T-11-02) and false-positive-circuit-trip (T-11-04) mitigations implemented once in `ResilienceService` and inherited here.
