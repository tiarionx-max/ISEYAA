<objective>
User reported (via screenshot) that Naira amounts render visually broken — the ₦ symbol appears to have a strikethrough / overlapping-glyph artifact — on the ride-fare screen ("₦1,017") and the profile wallet stat ("₦0k"). Root cause, confirmed by direct file inspection: both affected styles set `fontFamily: FONT_DISPLAY` (Android: generic `'serif'` alias) or `fontFamily: FONT_MONO` (Android: generic `'monospace'` alias) — `mobile/lib/tokens.ts` defines these as bare OS font-family names despite a comment claiming real custom fonts ("Instrument Serif / JetBrains Mono") are bundled; none actually are. Android's generic serif/monospace aliases lack a proper glyph for U+20A6 and substitute a broken fallback. `FONT_UI` (Android: `'sans-serif'`) is used all over the app for body text with zero rendering complaints, confirming it has correct glyph coverage.

Purpose: Every ₦-prefixed amount anywhere in the mobile app must render as a clean, correct glyph on Android.
Output: A repo-wide sweep (grep for `₦` across `mobile/app/**/*.tsx` found 25 files) traced every render site to its style; for the subset that both (a) actually render the ₦ character and (b) use `fontFamily: FONT_DISPLAY`/`FONT_MONO`, that one property was changed to `fontFamily: FONT_UI`, adding the `FONT_UI` import where missing. Styles using the same font tokens for non-currency text (headings, labels) were left untouched, as were currency styles that never actually render the glyph (e.g. wallet.tsx's `balanceAmount`/`balanceCurrency`, which show a bare number and the literal text "NGN").
</objective>
