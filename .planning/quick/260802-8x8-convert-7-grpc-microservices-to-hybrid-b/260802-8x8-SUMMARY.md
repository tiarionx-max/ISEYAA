# Phase quick Plan 260802-8x8: Convert 7 gRPC microservices to hybrid gRPC+HTTP bootstrap Summary

Converted the last 7 pure-gRPC microservices (auth, wallet, events, stays, marketplace, admin, ai) to the hybrid gRPC+HTTP bootstrap already proven on notifications-service and the other 4 Phase-21 services, closing the gap where Railway had no HTTP surface to healthcheck against for these 7.

## What Was Built

**Task 1 — main.ts hybrid bootstrap, health.controller.ts, app.module.ts wiring (21 files, 7 services):**

For each of auth (5001), wallet (5002), events (5003), stays (5004), marketplace (5005), admin (5006), ai (5007):

- `src/main.ts` rewritten in full: replaced `NestFactory.createMicroservice(AppModule, {...})` + bare `await app.listen()` with `NestFactory.create(AppModule)` + `app.connectMicroservice<MicroserviceOptions>({...})` + `await app.startAllMicroservices()` + a Swagger `/docs` setup block + `await app.listen(process.env.PORT ?? 8080)`. The gRPC transport options now wrap `protoPath` in a two-element array with `grpc-health-check`'s `healthCheckProtoPath`, and register a `grpc-health-check` `HealthImplementation` via `onLoadPackageDefinition` (byte-identical pattern to notifications-service). The pre-existing IPv6 bind comment and `url: '[::]:<port>'` value (already fixed in an earlier commit, e38cb1f) were preserved verbatim — no service was reverted to `0.0.0.0`.
- `src/health.controller.ts` created new in all 7 services, byte-identical to `notifications-service/src/health.controller.ts`: a `HealthController` with `@Get('healthz')` + `@HealthCheck()` returning `this.health.check([])`.
- `src/app.module.ts` edited additively in all 7 services: added `TerminusModule` (from `@nestjs/terminus`) to the `imports` array and `HealthController` (from `./health.controller`) to the `controllers` array, alongside every existing entry. No existing import, module, or controller was removed or reordered.

**Task 2 — Dockerfile symlink hoist + EXPOSE 8080, railway.toml healthcheckPath (14 files, 7 services):**

For each of the 7 services:

- `Dockerfile`: inserted the platform-express symlink hoist comment block + `RUN mkdir -p node_modules/@nestjs && ln -s /app/backend/node_modules/@nestjs/platform-express node_modules/@nestjs/platform-express` immediately after `RUN cd packages/proto && npx tsc -p tsconfig.json` and before `COPY backend/ ./backend/` (verbatim from notifications-service's Dockerfile). Added a new `EXPOSE 8080` line directly after the service's existing `EXPOSE <gRPC-port>` line. `CMD`, `npm ci`, the sharp musl-install line, `prisma generate`, and `nest build <service>` were all left untouched — none of these 7 services' `CMD` lines include the `--require ./backend/dist/src/instrumentation.js` flag (that remains notifications-service-specific, as instructed).
- `railway.toml`: inserted `healthcheckPath = "/healthz"` and `healthcheckTimeout = 60` under `[deploy]`, positioned between the existing `watchPaths` line and `restartPolicyType = "on_failure"` line. `[build]`, `watchPaths`, `restartPolicyType`, and `restartPolicyMaxRetries` were left untouched.
