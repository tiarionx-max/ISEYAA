<objective>
Metro's dev server was reliably timing out with "Failed to start watch mode" when starting on this Windows machine. Root cause: `metro.config.js`'s `watchFolders` included the entire monorepo root (`backend/`, `web/`, `packages/proto/`, `.git/`, `.planning/`, `.claude/`, every workspace's `node_modules`), and with Watchman not installed, Metro falls back to Node's `fs.watch`-based `NodeWatcher`, which times out trying to recursively register watches across that much unrelated tree on Windows.

Fix: scope `watchFolders` to only what `mobile/` actually resolves from the monorepo — `shared/` (via the `@iseyaa/shared` path alias already in `mobile/tsconfig.json`) and the root `node_modules` (for hoisted npm-workspaces dependencies). This excludes `backend/`, `web/`, `packages/proto/`, and all dotfolders, which mobile never imports from.

Purpose: Unblock local mobile development/testing on Windows without requiring Watchman (which needs admin rights to install via Chocolatey in this environment).
Output: `mobile/metro.config.js`'s `watchFolders` array narrowed from `[...defaults, monorepoRoot]` to `[...defaults, shared/, node_modules/]`.
</objective>
