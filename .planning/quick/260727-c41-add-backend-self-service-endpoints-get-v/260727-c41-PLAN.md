  const user = await this.prisma.user.findUnique({
    where: { id: userId, deletedAt: null },
    select: { registeredRoles: true },

    where: { id: userId },
    data: {

      role: 'HOST' as UserRole,
    },
    select: USER_SELECT,
  });
  return updated;
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile/web client → `GET /vendors/me`, `/products/mine`, `/orders/vendor` | Authenticated caller's own JWT `userId` resolves their vendor scope — no client-supplied vendor/product/order id accepted |
| Mobile/web client → `POST /users/me/become-organiser` | Self-service role escalation triggered entirely by client-side user intent, no admin approval step |
| Mobile/web client → `GET /events/mine` | Authenticated caller's own JWT `userId` resolves their organizer scope — no client-supplied organizer id accepted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-quick-01 | Elevation of Privilege | `POST /users/me/become-organiser` | accept | Mirrors the already-shipped, already-accepted `become-host`/`become-guide` self-service pattern — ORGANISER grants only the ability to create/manage one's own events (still gated by `@Roles(ORGANISER)` + ownership checks on every mutating event route), not a platform-wide privilege; consistent with the existing risk posture for this role tier |
| T-quick-02 | Information Disclosure (cross-tenant data leak) | `GET /products/mine`, `GET /orders/vendor`, `GET /vendors/me` | mitigate | All three resolve the vendor scope exclusively from `findMyVendor(user.userId)` derived from the authenticated JWT — no route accepts a vendor id as a path/query param, so one vendor cannot enumerate or fetch another vendor's products/orders |
| T-quick-03 | Information Disclosure (cross-tenant data leak) | `GET /events/mine` | mitigate | Scoped exclusively to `organizerId: user.userId` from the JWT — no organizer id accepted as a client-supplied parameter |
| T-quick-04 | Tampering (route shadowing) | `GET /products/mine`, `GET /events/mine` | mitigate | Both declared before their respective `GET /:id` routes in file order, preventing Express/NestJS from matching `mine` as an `:id` value and routing to the wrong (or a 404/500-shaped) handler |

</threat_model>
